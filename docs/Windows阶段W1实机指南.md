# Windows 阶段 W1 实机指南

## 1. 用途与结论边界

本文保留为 Windows 10 22H2 x64 标准用户环境复现 W1 实时纵切的历史指南。W1 已按已知分类兼容性和未量化性能风险带限制通过；当前累计验收进入[Windows 阶段 W2A 实机指南](Windows阶段W2A实机指南.md)。预览产物仍不是稳定 Release，也不代表已支持安装或自动更新。

GitHub Actions 通过只证明静态契约、Core 单元测试、Release 构建和非打包发布成功，不能替代真实 Mihomo、Windows Credential Manager、Windows 10 生命周期和资源占用验收。测试结果应回传项目维护者，由父工作区保存带日期验收记录。

## 2. 测试前准备

准备以下环境和信息：

- Windows 10 22H2 x64，使用标准用户运行，不以管理员身份启动应用。
- 可启动、停止并恢复的本机 Mihomo；Controller 监听地址必须是 `127.0.0.1` 或 `::1`，并包含明确端口。
- 一组无 Secret 的测试配置，以及一组正确 Secret 和错误 Secret 的测试条件。
- 可分别制造 Proxy 与 DIRECT 流量的受控测试方式；不要在截图、录屏或 Issue 中暴露真实节点、目标、规则、订阅地址或 Secret。
- 任务管理器或资源监视器，用于记录 CPU、内存工作集和磁盘活动。

从目标分支的“Windows 构建与测试”工作流手动运行或下载对应成功运行的 `mihomo-meter-windows-w1-x64-<提交>` artifact。完整解压后运行 `MihomoMeter.Windows.App.exe`，不要只复制单个 EXE。未签名产物可能触发 Windows 安全提示；只在确认 artifact 来自本项目目标提交后选择继续，不要关闭系统安全机制。

开始前记录目标提交、工作流运行链接、Windows 版本、Mihomo 版本和是否存在旧配置。普通设置地址位于：

```text
%LOCALAPPDATA%\HongXunPan\MihomoMeter\settings.json
```

凭据在 Windows“凭据管理器”的“Windows 凭据”中以 Generic Credential 保存，Target Name 固定为：

```text
com.HongXunPan.MihomoMeter.controller
```

## 3. 首次连接与安全检查

1. 确认没有正在运行的 Mihomo Meter，启动应用，主窗口应出现且悬浮图标默认关闭。
2. 依次提交远程地址、缺失端口和带额外路径的地址，应用应拒绝这些输入，不应建立请求或保存配置。
3. 填写无 Secret 的本地 Controller；若同地址已有凭据，勾选“本次明确不使用 Secret”。连接后应显示 Mihomo 版本、已连接状态和四类速率入口。
4. 退出并检查 `settings.json`：只应包含版本和规范化回环地址，不得出现 Secret、响应正文、节点或连接明细。
5. 改用正确 Secret 连接，明确退出后重新启动；应用应从凭据管理器读取 Secret 并自动连接，不强制弹出主窗口。
6. 打开凭据管理器，确认 Target Name 精确匹配固定值；不要截图或导出凭据内容。
7. 输入错误 Secret。应用应显示鉴权失败，不循环重试；再次启动后仍应使用上一份已验证配置，错误 Secret 不得覆盖它。

如果设置文件出现 Secret、错误配置覆盖既有有效配置、需要管理员权限或无法从凭据管理器删除目标项，立即停止测试并报告。

## 4. 实时分类与状态机

按顺序执行并记录现象与大致时间：

1. 连接后先保持无流量，四类无有效窗口时应显示不可用状态，不以旧值或伪造零值表示实时结果。
2. 仅制造 Proxy 流量，Proxy 上传/下载应变化，DIRECT、REJECT 与未知不得静默累加到 Proxy。
3. 仅制造 DIRECT 流量，DIRECT 上传/下载应变化，与 Proxy 保持可区分。
4. 停止受控流量后，速率应在新窗口内回落，不长期保留旧速率。
5. 停止 Mihomo：最后一帧约两秒后应进入“数据已超时”并清空实时值，约五秒后应进入自动重连。
6. 恢复 Mihomo：应用应重新验证、重建首帧基线后恢复实时值，不应短暂闪回断开前速率。
7. 主动点击“断开”，等待至少十秒，确认没有后台重连；随后立即重新连接，只应存在一个有效 WebSocket 会话。
8. 使用错误 Secret 验证终止状态后，再使用正确 Secret 恢复，旧会话不得覆盖新状态。

REJECT 和未知只有在可控、安全的测试条件下验证；若本轮无法稳定制造，应如实记录“未覆盖”，不得用 Proxy 或 DIRECT 结果代替。

## 5. W0 生命周期回归

1. 关闭主窗口，确认进程继续运行且通知区域图标仍存在；再次打开应复用同一主窗口。
2. 连续启动应用两次，确认只保留一个进程，已有实例的主窗口被唤起。
3. 从通知区域开启悬浮图标，确认它置顶、可拖动、不会取得输入焦点；单击能打开主窗口，关闭后可再次开启。
4. 在连接中关闭主窗口，确认实时监控仍继续；通知区域提示应反映当前连接状态。
5. 执行睡眠与恢复，确认没有重复 WebSocket、通知区域图标或悬浮窗口。
6. 从通知区域选择“退出”，确认请求和待重连被取消，窗口、图标和进程均无残留。

任何单实例、关闭隐藏、悬浮入口或明确退出回归都属于 W1 停机条件，不能以实时速率可用为由忽略。

## 7. 结果回传与清理

回传内容至少包括：提交 SHA、工作流运行链接、系统与 Mihomo 版本、各场景通过/失败/未覆盖、stale 与重连实测时间、资源表、是否使用标准用户，以及异常的最小复现步骤。不得附带 Secret、真实地址以外的连接目标、节点、规则、订阅信息或完整响应。

测试结束后从通知区域明确退出。若不再保留测试配置，可删除 `settings.json`，并在 Windows 凭据管理器中删除固定 Target Name 的 Generic Credential；不要把用户配置或凭据复制进仓库。当前 W1 已带限制放行，本文未留存的分类兼容性和精确资源数据继续作为后续观察项，不得扩大为所有配置或量化性能均已验证。
