# 登录后启动实现契约

## 1. 范围

Mihomo Meter 在 macOS 与 Windows 提供默认关闭的“登录后启动”设置。该能力只在当前用户登录桌面会话后启动应用，不实现 macOS LaunchDaemon、Windows Service、计划任务或管理员级开机进程。

安装、升级和首次运行不自动开启。启用后应用保持既有静默形态：macOS 只显示状态栏，Windows 只显示通知区域；不得自动显示普通窗口、首次连接引导或抢占焦点。

## 2. macOS

macOS 使用 `ServiceManagement` 的 `SMAppService.mainApp` 管理主应用登录项，不增加辅助应用。设置界面直接映射系统的 enabled、not registered、requires approval 和 not found 状态，不在 `UserDefaults` 保存平行布尔值。

系统要求批准时，应用显示明确说明并打开系统“登录项”设置。用户从系统设置返回应用后重新读取状态；注册或注销失败只影响该开关，不得中断监控与账本。

## 3. Windows

Windows 非打包程序使用 64 位当前用户注册表：

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
```

固定值名为 `Mihomo Meter`，值为带引号的当前可执行文件绝对路径及 `--startup`。设置页直接读取注册表；若登录项仍指向另一份安装版或便携版，必须明确提示并允许用户改为当前程序。

`--startup` 只表达登录启动原因：没有 Controller 配置也不显示首次引导；发现既有主实例时直接退出，不触发窗口恢复。普通手动重复启动继续前置既有实例。

## 4. 安装与卸载

NSIS 不在安装页提供默认勾选项，也不主动创建 Run 值。覆盖升级保持原安装路径时，已开启的登录项自然继续有效。

卸载只在 Run 值精确等于当前安装目录程序及 `--startup` 参数时删除；若值指向另一份便携程序，不得误删。卸载继续保留普通用户数据和 Credential Manager 凭据。

便携版可以开启登录启动；移动或删除程序后旧绝对路径失效，需要从新位置重新开启。

## 5. 验证

日常 macOS 校验执行严格 Swift 格式检查和 Xcode 工程语法检查；Windows 在非 Windows 主机执行 `python3 scripts/validate_windows.py`、XAML 解析、安装器静态契约和 `git diff --check`。完整双端构建由 CI 执行。

真实平台还需确认 macOS 系统批准与撤销、Windows 10 22H2 x64 标准用户登录启动、安装版与便携版、已有实例不抢焦点、覆盖升级保留、卸载定向清理以及关闭后下次登录不再启动。
