# 跨平台共享核心技术方案

## 1. 文档定位

- 状态：P0 已完成，P1.1 测试/CI 差分门禁，尚未切换生产算法
- 更新日期：2026-08-11
- 平台基准：macOS 现行领域行为与展示口径

本文是源码仓跨平台共享核心的技术真相源。P0 已验证 Rust 核心、稳定 C ABI、Swift 调用、C# 调用和 Windows 发布载荷。P1.1 在测试与 CI 中让现有平台格式化器和共享核心接收同一输入并比较结果，不改变 Controller、账本、界面、现有领域实现或生产调用链；差分通过不等于允许切换生产算法。

## 2. 目标与非目标

目标是让适合跨端复用的领域模型、状态机与算法逐步收敛到同一份实现，同时保留 AppKit、SwiftUI、WinUI 3、Win32 和平台系统服务。当前共享纯函数只实现 ABI 版本与十进制流量缩放，验证小于 10 保留两位、10 至小于 100 保留一位、100 及以上不保留小数，Byte 单位不显示小数。

P1.1 不共享 View、窗口生命周期、网络、Controller 解码、Keychain、Windows Credential Manager、SQLite、更新器、本地化文案或异步调度，也不删除或替换 Swift/C# 现有算法。Swift 与 C# 生产格式化器仍是结果基准，共享核心只在测试进程中被调用。

## 3. 工程结构

```text
SharedCore/
├── Cargo.toml
├── src/lib.rs
├── TestVectors/traffic_scale.json
├── include/
│   ├── mihomo_meter_shared_core.h
│   └── module.modulemap
└── Adapters/Swift/
    ├── MihomoMeterSharedCoreAdapter.swift
    └── Probe/main.swift
```

共享核心固定使用 Rust 1.97.1，只依赖标准库，并同时产出 `staticlib`、`cdylib` 与测试使用的 `rlib`。macOS 探针静态链接核心；Windows 测试通过 C# `DllImport` 加载 `mihomo_meter_shared_core.dll`。平台适配器只做类型转换和错误映射，不复制算法。`TestVectors` 是双端差分唯一输入所有者，不包含真实流量或用户数据。

## 4. ABI 与安全边界

C ABI 版本固定从 `1` 开始，所有数值使用固定宽度类型。当前只导出 `mm_core_abi_version` 与 `mm_scale_traffic`；调用方提供输出结构体空间，Rust 不向平台返回需要跨边界释放的内存。

导出函数不得让 panic、Rust 引用、集合、字符串或异常越过 ABI。新增枚举只能追加稳定值；删除、改序、改字段宽度或改变结构体布局都必须提升 ABI 主版本。后续有状态对象只能使用不透明句柄和显式创建、重置、销毁函数，C# 端必须以 `SafeHandle` 管理。

## 5. 构建与交付

macOS 使用 `scripts/test_shared_core_macos.sh` 构建并运行 Swift 探针，临时可执行文件只进入被忽略的 `.codex-tmp/`，Rust 产物只进入被忽略的 `.build/`。Windows 使用 `scripts/build_shared_core_windows.ps1` 构建固定 `x86_64-pc-windows-msvc` DLL；Tests 与 App 工程从同一路径复制 DLL，发布目录和后续打包载荷必须包含该文件。

`rust-toolchain.toml` 和 `Cargo.lock` 必须提交。P1.1 不引入 Cargo 第三方依赖、绑定生成器或下载脚本；CI 通过 rustup 安装固定工具链。源码仓不提交静态库、DLL、探针可执行文件或工具链缓存。

## 6. 验证与停止条件

`SharedCore/TestVectors/traffic_scale.json` 固定使用 schema 版本 `1`，字节值以升序、无重复的十进制字符串保存，覆盖单位阈值、精度阈值、舍入边界与 `UInt64.max`，避免 JSON 数字精度损失。macOS 探针同时调用真实 `TrafficStatisticsFormatter`、`TrafficRateFormatter` 和 Swift 共享核心适配器；Windows 测试同时调用真实 `TrafficDisplayUnits` 和 C# 共享核心适配器。任一展示字符串不同即失败，差分过程不写运行日志、不进入用户状态，也不改变生产结果。

本地 macOS 最小验证：

```bash
python3 scripts/validate_shared_core.py
scripts/test_shared_core_macos.sh
xcrun swift format lint --recursive --strict Sources Tests SharedCore/Adapters/Swift
```

Windows 完整入口仍为 `pwsh -File scripts/validate_windows.ps1`，固定先校验共享核心、运行 Rust 测试并构建 DLL，再执行包含统一向量差分的 Core 测试、既有静态检查、App 构建、发布与打包。非 Windows 主机只能确认 JSON、工程引用和代码标记等静态契约，不能据此声称 Windows DLL 已加载或安装器已通过。

出现 ABI 无法保持窄接口、共享核心需要接触 Secret 或完整连接目标、迁移会改变现行 macOS 结果、DLL 未进入发布载荷、必须引入未批准依赖，或任一平台无法独立回退到旧实现时，立即停止并重新规划。

## 7. 后续阶段

P1.2 才评估运行期影子或正式切换流量缩放调用；必须单独设计 macOS 静态库链接、签名与 Library Validation，以及 Windows DLL 加载失败和回退策略，并获得确认。之后的纯函数候选是 Proxy 类型归一化与分类、配额目标点数和采样；P2 才评估连接差值、速率窗口与聚合状态机。网络、持久化、凭据和 View 仍留在平台层，除非另有独立方案和实机证据。
