# 跨平台共享核心技术方案

## 1. 文档定位

- 状态：P1.3-4 三类流量格式受保护主路径已启用；待双端实机验收
- 更新日期：2026-08-11
- 平台基准：macOS 现行领域行为与展示口径

本文是源码仓跨平台共享核心的技术真相源。P0 已验证 Rust 核心与稳定 C ABI，P1.1 已建立统一向量差分，P1.2a 已把核心接入双端生产构建与启动加载链。P1.2b 让双端生产字节数、完整速率和紧凑速率格式化器执行原生结果与共享核心结果影子比较，双端运行态门禁已于 2026-08-11 通过；P1.3-1 建立受保护主路径路由与自动回退基础设施，P1.3-2 至 P1.3-4 已让三类流量格式在精确一致时返回共享文本，任何异常仍逐次回退原生文本。

## 2. 目标与非目标

目标是让适合跨端复用的领域模型、状态机与算法逐步收敛到同一份实现，同时保留 AppKit、SwiftUI、WinUI 3、Win32 和平台系统服务。当前共享纯函数只实现 ABI 版本与十进制流量缩放，验证小于 10 保留两位、10 至小于 100 保留一位、100 及以上不保留小数，Byte 单位不显示小数。

P1.2b 不共享 View、窗口生命周期、网络、Controller 解码、Keychain、Windows Credential Manager、SQLite、更新器、本地化文案或异步调度，也不删除或替换 Swift/C# 现有算法。生产进程在主实例启动时执行一次固定 `1,500` 字节探针；其后每次生产字节数或速率格式化都先生成原生文本，再以相同输入调用共享核心缩放和平台结果渲染器进行比较。共享调用、渲染或诊断失败均不得改变原生返回值。

Windows 原先位于通知区投影中的紧凑速率算法已下沉到 Core，与字节数和完整速率原生算法共同形成可独立测试的基准；App 展示层只负责触发影子比较和组合文案。macOS 继续以既有 `TrafficStatisticsFormatter`、`TrafficRateFormatter` 原生算法为基准。

## 3. 工程结构

```text
SharedCore/
├── Cargo.toml
├── src/lib.rs
├── TestVectors/traffic_scale.json
├── include/
│   ├── mihomo_meter_shared_core.h
│   └── module.modulemap
└── Adapters/Swift/
    ├── MihomoMeterSharedCoreAdapter.swift
    ├── SharedCoreTrafficDisplayFormatter.swift
    └── Probe/main.swift
```

共享核心固定使用 Rust 1.97.1，只依赖标准库，并同时产出 `staticlib`、`cdylib` 与测试使用的 `rlib`。macOS App 与测试静态链接对应架构核心；Windows App 与测试通过 C# `DllImport` 加载同一发布 DLL。平台适配器只做类型转换和错误映射，不复制算法。`TestVectors` 是双端差分唯一输入所有者，不包含真实流量或用户数据。

## 4. ABI 与安全边界

C ABI 版本固定从 `1` 开始，所有数值使用固定宽度类型。当前只导出 `mm_core_abi_version` 与 `mm_scale_traffic`；调用方提供输出结构体空间，Rust 不向平台返回需要跨边界释放的内存。

导出函数不得让 panic、Rust 引用、集合、字符串或异常越过 ABI。新增枚举只能追加稳定值；删除、改序、改字段宽度或改变结构体布局都必须提升 ABI 主版本。后续有状态对象只能使用不透明句柄和显式创建、重置、销毁函数，C# 端必须以 `SafeHandle` 管理。

## 5. 构建与交付

macOS 使用 `scripts/build_shared_core_macos.sh` 按 `arm64`、`x86_64` 构建静态库，`Config.xcconfig` 按 Xcode 当前架构显式链接对应 `.a` 归档，不得通过 `-l` 搜索选择同名 dylib；Debug、DMG 和发布 CI 必须在 Xcode 构建前调用该脚本。`scripts/test_shared_core_macos.sh` 继续负责 Rust 检查、单测、静态链接门禁和统一向量差分。Windows 使用 `scripts/build_shared_core_windows.ps1` 构建固定 `x86_64-pc-windows-msvc` DLL；Tests 与 App 工程从同一路径复制 DLL，发布目录和后续打包载荷必须包含该文件。

`rust-toolchain.toml` 和 `Cargo.lock` 必须提交。P1.2b 不引入 Cargo 第三方依赖、绑定生成器或下载脚本；CI 通过 rustup 安装固定工具链及 macOS 双架构目标。源码仓不提交静态库、DLL、探针可执行文件或工具链缓存。

## 6. 验证与停止条件

`SharedCore/TestVectors/traffic_scale.json` 固定使用 schema 版本 `1`，字节值以升序、无重复的十进制字符串保存，覆盖单位阈值、精度阈值、舍入边界与 `UInt64.max`，避免 JSON 数字精度损失。macOS 探针同时调用真实 `TrafficStatisticsFormatter`、`TrafficRateFormatter` 和 Swift 共享核心适配器；Windows 测试同时调用真实 `TrafficDisplayUnits` 和 C# 共享核心适配器。任一展示字符串不同即失败，差分过程不写运行日志、不进入用户状态，也不改变生产结果。

生产启动探针固定检查 ABI `1` 和 `1,500` 字节缩放结果。macOS 将结果写入一次现有诊断事件；Windows 只在显式启用启动控制台时输出一次阶段。生产影子按“格式类型 + 粗粒度状态”在单次进程生命周期内去重；正常时三类格式各记录一次 `matched`，异常状态首次出现时也记录一次。macOS 事件进入既有容量和保留期受限的诊断日志，Windows 仅进入显式启用的启动控制台。两端都不得记录输入字节、原生或共享文本、路径、原始异常、Secret 或连接目标；ABI、加载、结果不一致或未知失败必须被转换为粗粒度状态并继续使用原生结果。双端实机步骤与放行口径见[跨平台共享核心 P1.2b 运行态验收指南](跨平台共享核心P1.2b运行态验收指南.md)。

本地 macOS 最小验证：

```bash
python3 scripts/validate_shared_core.py
scripts/test_shared_core_macos.sh
xcrun swift format lint --recursive --strict Sources Tests SharedCore/Adapters/Swift
```

Windows 完整入口仍为 `pwsh -File scripts/validate_windows.ps1`，固定先校验共享核心、运行 Rust 测试并构建 DLL，再执行包含统一向量差分的 Core 测试、既有静态检查、App 构建、发布与打包。非 Windows 主机只能确认 JSON、工程引用和代码标记等静态契约，不能据此声称 Windows DLL 已加载或安装器已通过。

出现 ABI 无法保持窄接口、共享核心需要接触 Secret 或完整连接目标、迁移会改变现行 macOS 结果、DLL 未进入发布载荷、必须引入未批准依赖，或任一平台无法独立回退到旧实现时，立即停止并重新规划。

## 7. 后续阶段

双端构建、启动、持续影子观测和[运行态实机门禁](跨平台共享核心P1.2b运行态验收指南.md)已通过。P1.3 按[受保护主路径技术方案](跨平台共享核心P1.3受保护主路径技术方案.md)分阶段推进：先建立不改变生产输出的路由基础设施，再依次切换字节数、完整速率和紧凑速率；任一异常按单次调用回退原生结果。P1.2b 不提供运行时切换开关，也不根据影子结果自动切换。之后的纯函数候选是 Proxy 类型归一化与分类、配额目标点数和采样；网络、持久化、凭据和 View 仍留在平台层。
