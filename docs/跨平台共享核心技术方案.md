# 跨平台共享核心技术方案

## 1. 文档定位

- 状态：P1.4 双端运行态门禁已通过，P2-2 分类影子已接入且不改变生产结果
- 更新日期：2026-08-12
- 平台基准：macOS 现行领域行为与展示口径

本文是源码仓跨平台共享核心的技术真相源。P0 已验证 Rust 核心与稳定 C ABI，P1.1 已建立统一向量差分，P1.2a 已把核心接入双端生产构建与启动加载链。P1.2b 让双端生产流量格式执行影子比较；P1.3 建立受保护主路径，P1.4 让三类格式共享优先、异常时懒回退原生算法并通过双端门禁。P2 已建立代理类型纯分类 ABI、双端适配器与独立统一向量；生产影子和受保护主路径均通过双端门禁，下一步进入 P2-6 懒原生回退。

## 2. 目标与非目标

目标是让适合跨端复用的领域模型、状态机与算法逐步收敛到同一份实现，同时保留 AppKit、SwiftUI、WinUI 3、Win32 和平台系统服务。当前共享纯函数实现 ABI 版本、十进制流量缩放和原始代理类型分类；分类 ABI 尚未接入生产路由。流量缩放验证小于 10 保留两位、10 至小于 100 保留一位、100 及以上不保留小数，Byte 单位不显示小数。

共享核心不覆盖 View、窗口生命周期、网络、Controller 解码、Keychain、Windows Credential Manager、SQLite、更新器、本地化文案或异步调度，也不删除 Swift/C# 现有算法。生产进程在主实例启动时执行一次固定 `1,500` 字节探针；三类格式均先调用共享核心，失败才计算原生文本。Windows 紧凑速率无值占位不进入共享核心。共享调用、渲染或诊断失败均不得影响最终展示。

Windows 原先位于通知区投影中的紧凑速率算法已下沉到 Core，与字节数和完整速率原生算法共同形成可独立测试的基准；App 展示层只负责触发影子比较和组合文案。macOS 继续以既有 `TrafficStatisticsFormatter`、`TrafficRateFormatter` 原生算法为基准。

## 3. 工程结构

```text
SharedCore/
├── Cargo.toml
├── src/lib.rs
├── TestVectors/
│   ├── proxy_type_classification.json
│   └── traffic_scale.json
├── include/
│   ├── mihomo_meter_shared_core.h
│   └── module.modulemap
└── Adapters/Swift/
    ├── MihomoMeterSharedCoreAdapter.swift
    ├── SharedCoreTrafficDisplayFormatter.swift
    └── Probe/main.swift
```

共享核心固定使用 Rust 1.97.1，只依赖标准库，并同时产出 `staticlib`、`cdylib` 与测试使用的 `rlib`。macOS App 与测试静态链接对应架构核心；Windows App 与测试通过 C# `DllImport` 加载同一发布 DLL。平台适配器只做类型转换和错误映射，不复制算法。`TestVectors` 是双端差分唯一输入所有者，不包含真实流量或用户数据。

## 4. ABI 与安全边界

C ABI 版本固定从 `1` 开始，所有数值使用固定宽度类型。当前导出 `mm_core_abi_version`、`mm_scale_traffic` 与 `mm_classify_proxy_type`；调用方提供输入缓冲区和输出结构体空间，Rust 不向平台返回需要跨边界释放的内存。分类 ABI 只接受不超过 64 字节的 ASCII，并以稳定非零错误码拒绝空指针组合、非 ASCII 和超长输入；详细契约由 P2 方案持有。

导出函数不得让 panic、Rust 引用、集合、字符串或异常越过 ABI。新增枚举只能追加稳定值；删除、改序、改字段宽度或改变结构体布局都必须提升 ABI 主版本。后续有状态对象只能使用不透明句柄和显式创建、重置、销毁函数，C# 端必须以 `SafeHandle` 管理。

## 5. 构建与交付

macOS 使用 `scripts/build_shared_core_macos.sh` 按 `arm64`、`x86_64` 构建静态库，`Config.xcconfig` 按 Xcode 当前架构显式链接对应 `.a` 归档，不得通过 `-l` 搜索选择同名 dylib；Debug、DMG 和发布 CI 必须在 Xcode 构建前调用该脚本。`scripts/test_shared_core_macos.sh` 继续负责 Rust 检查、单测、静态链接门禁和统一向量差分。Windows 使用 `scripts/build_shared_core_windows.ps1` 构建固定 `x86_64-pc-windows-msvc` DLL；Tests 与 App 工程从同一路径复制 DLL，发布目录和后续打包载荷必须包含该文件。

`rust-toolchain.toml` 和 `Cargo.lock` 必须提交。P1.2b 不引入 Cargo 第三方依赖、绑定生成器或下载脚本；CI 通过 rustup 安装固定工具链及 macOS 双架构目标。源码仓不提交静态库、DLL、探针可执行文件或工具链缓存。

## 6. 验证与停止条件

`SharedCore/TestVectors/traffic_scale.json` 固定使用 schema 版本 `1`，字节值以升序、无重复的十进制字符串保存，覆盖单位阈值、精度阈值、舍入边界与 `UInt64.max`，避免 JSON 数字精度损失。`proxy_type_classification.json` 独立覆盖 P2 现行协议、归一化、未知与输入边界。macOS 探针和 Windows 测试分别让真实原生实现与平台共享适配器读取同一向量差分。任一结果不同即失败，差分过程不写运行日志、不进入用户状态，也不改变生产结果。

生产启动探针固定检查 ABI `1` 和 `1,500` 字节缩放结果。macOS 将结果写入一次现有诊断事件；Windows 只在显式启用启动控制台时输出一次阶段。路由事件按“格式 + 来源 + 状态”在单次进程内去重；三类格式成功均记录 `succeeded`，异常状态首次出现时也记录一次。macOS 事件进入既有容量和保留期受限的诊断日志，Windows 仅进入显式启用的启动控制台。两端都不得记录输入字节、原生或共享文本、路径、原始异常、Secret 或连接目标；ABI、加载或未知失败必须转换为粗粒度状态并继续使用原生结果。

本地 macOS 最小验证：

```bash
python3 scripts/validate_shared_core.py
scripts/test_shared_core_macos.sh
xcrun swift format lint --recursive --strict Sources Tests SharedCore/Adapters/Swift
```

Windows 完整入口仍为 `pwsh -File scripts/validate_windows.ps1`，固定先校验共享核心、运行 Rust 测试并构建 DLL，再执行包含统一向量差分的 Core 测试、既有静态检查、App 构建、发布与打包。非 Windows 主机只能确认 JSON、工程引用和代码标记等静态契约，不能据此声称 Windows DLL 已加载或安装器已通过。

出现 ABI 无法保持窄接口、共享核心需要接触 Secret 或完整连接目标、迁移会改变现行 macOS 结果、DLL 未进入发布载荷、必须引入未批准依赖，或任一平台无法独立回退到旧实现时，立即停止并重新规划。
