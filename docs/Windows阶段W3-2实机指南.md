# Windows 阶段 W3-2 实机指南

## 1. 范围与环境

本文用于 Windows 10 22H2 x64 标准用户验证人工更新检查、平台实际版本、Release 下载指引和 W3-1 安装回归。W3-2 采用首发前、首发后两段式门禁；前置结果记录且用户明确确认前不得创建稳定 Release。

测试期间不要上传 Controller Secret、订阅 URL、真实主机名、应用名称、进程路径、数据库、设置文件或本机路径。反馈只需提供提交 SHA、Action run、测试版本、描述状态和失败步骤。

## 2. 自动化前提

1. 确认 Windows 静态契约、Core 单元测试、App x64 Release 构建、自包含发布、NSIS、ZIP 和 SHA-256 全部通过。
2. 确认统一发布工作流从 `main` 以 `platform=windows`、`release_mode=draft` 完成，未标记 Latest；后续 stable 必须用相同平台原样提升该同版本候选，不重新构建或替换资产。
3. draft 必须包含新生成的 `windows-release.json`、从 `v0.5.1` 元数据补建的 `macos-release.json`、原样沿用的 `appcast.xml`、跨平台下载指引和本次 Windows 资产，不得包含旧 DMG。
4. 核对 Windows 描述为本次版本，macOS 描述仍为 `0.5.1` 且指向 `v0.5.1` 原始资产；两个 JSON 不得包含用户数据或本机信息。

## 3. 两段式版本检查

1. **首发前**：打开侧边栏“关于与更新”，确认当前版本正确；固定 Latest 描述尚不存在时应显示暂不可用，连续点击只存在一次检查，页面和监控数据不闪烁。
2. **首发后**：首个 Windows-only 稳定 Release 只能在前置结果记录且用户明确确认后发布；使用该 Windows 版本检查时必须显示“已是最新版本”，并可打开描述中的本仓库 HTTPS Release。Mac 应继续停留在 `0.5.1`，不得收到本次 Windows 版本更新提示。
3. **下一 Windows 稳定版**：保留上一稳定版，在新版本发布后检查，确认只提示 Windows 实际新版本而非 Latest Tag；点击“打开发布页面”不得直接下载或运行安装器。
4. 当前版本高于描述版本时不得提示降级；同版本、升级和降级比较仍由 Core 自动测试在每次 CI 锁定。
5. 不为提前测试增加可替换更新地址、环境开关或隐藏设置，也不创建后删除临时稳定 Release。

## 4. 失败与隔离

1. 断网、GitHub 限流、超时或服务器错误时，页面显示可恢复提示，实时监控、通知区域、统计、配额和连接分析继续工作。
2. 使用测试夹具验证非法 JSON、错误 schema、非 Windows 平台、非法版本、来源 Tag 不一致、非 HTTPS 或非本仓库页面时均拒绝更新。
3. draft、prerelease 与 Action artifact 不得成为稳定更新来源；应用固定 Latest 描述地址不存在时只报告暂不可用。
4. 更新检查不写入设置、SQLite、Credential Manager 或日志中的响应正文和下载地址。

## 5. Latest 下载指引

1. Release 正文顶部无需展开 Assets 即可看到 macOS 与 Windows 下载区。
2. 链接文字应直接说明 Apple Silicon Mac、Intel Mac、通用 Mac、Windows x64 安装版和 Windows x64 便携版，不要求用户理解文件名中的架构缩写。
3. 本次未构建的平台必须显示其实际版本与来源 Tag，并直接链接原 Release 资产；当前 Release 不得复制旧二进制。
4. 本次构建平台的文件名、描述版本、来源 Tag、下载 URL 与 SHA-256 必须一致。

## 6. Windows 安装回归

1. 校验安装器和便携 ZIP 的 SHA-256，确认 unsigned 提示符合公开说明。
2. 验证首次安装可选目录、运行中阻断、原位覆盖升级、同版本重装、开始菜单、卸载、数据与凭据保留。
3. 双向验证安装版、便携版和两个不同便携目录：后启动进程退出并恢复既有窗口，始终只有一个进程、一个通知区域图标和一套业务采样；主实例明确退出后才允许另一目录启动。
4. 回归通知区域、关闭隐藏、明确退出、悬浮图标，以及 W0-W2D 主要工作台。

## 8. 停止条件

出现误判其他平台版本、打开非本仓库页面、自动下载或安装、重复并发检查、网络失败中断监控、下载指引与描述不一致、复制旧二进制、安装生命周期或 W0-W2D 回归时，立即停止验收。首发前门禁通过只代表可申请首次稳定发布；首发后同版本结果和下一 Windows 稳定版发现更新必须继续回填，不得把待观察项写成已通过。
