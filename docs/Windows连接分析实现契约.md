## 2. 分段边界

Windows 连接分析按三个可独立验证的纵切推进：

1. **W2D-0 元数据覆盖率门禁**：只验证可靠分类为 Proxy 的连接是否具备可用主机名与应用元数据，不展示或保存真实值；
2. **W2D-1 实时连接**：门禁通过后再实现 Proxy/DIRECT 活动连接、双向速率、累计、时长、分组搜索和通知区域 Top 5；
3. **W2D-2 历史归因**：最后实现默认关闭的独立归因账本、30 日榜单、交叉筛选、趋势和记录覆盖率。

当前源码只承诺 W2D-0。它不包含活动连接列表、真实主机名或应用名展示、`find-process-mode` 诊断、归因 SQLite、历史榜单、趋势窗口或 Top 5。

## 3. W2D-0 数据边界

`MihomoConnectionResponse` 通过专用 JSON Converter 读取 `metadata.host`、`sniffHost`、`process` 与 `processPath`。Converter 在 Mihomo 基础设施边界内完成以下判断：

- 字符串去除首尾空白，UTF-8 超过 2,048 字节或类型异常时视为缺失；
- 主机名优先判断 `host`，再判断 `sniffHost`，IPv4、IPv6 和带方括号的 IP 不计为可识别主机名；
- 应用可用性依次参考 `processPath` 最外层 `.app`、`process` 和路径文件名，兼容 `/` 与 `\`；
- 解码结果只产生 `hasHostname` 与 `hasApplication` 两个布尔值。

真实主机名、进程名和完整进程路径只存在于 Converter 的局部解析过程，不进入领域模型、应用快照、属性通知、日志、Fixture 或持久化层。连接 ID 只作为本次内存会话的去重键，不展示、不记录、不落盘。

## 4. 领域与生命周期

`ConnectionAttributionCoverageTracker` 只消费已由 `ProxyClassifier` 可靠分类为 Proxy 的连接。未知、DIRECT 与 REJECT 不进入样本。

同一连接 ID 在本次会话只计一次；后续快照若补齐某项元数据，以逻辑或升级该连接的可识别状态，不重复增加总样本。对外快照只包含：

- Proxy 连接样本数；
- 主机名可识别数与比例；
- 应用可识别数与比例；
- 两者同时可识别数与比例。

新监控会话、用户断开、stale、重连、显式基线重置和 Mihomo 内核计数回退必须清空覆盖率样本。分类目录刷新只影响后续可靠分类，不把未知连接追溯计入 Proxy。

## 5. 展示边界

W2D-0 复用“实时监控”缓存视图，不新增窗口、导航模块、Coordinator 或 WebSocket。覆盖率区域固定展示四项聚合指标、隐私告知和受控流量提示。

界面刷新只更新对应文本属性，不替换整个视图或统计集合。没有 Proxy 样本时显示 `0 条` 与不可计算比例，不把无样本伪装为 0% 识别率。

## 6. 自动化门禁

Core 测试至少覆盖：

- 同一连接去重与后续可识别状态升级；
- reset 清除内存连接 ID；
- 只统计可靠 Proxy，排除 DIRECT 与未知；
- host/sniffHost、Windows 路径、IP、空白、异常类型和超长值；
- 计数器回退和 stale 所使用的基线清理接缝。

`scripts/validate_windows.py` 还检查 W2D 文档、领域/适配器/测试文件、UI 指标、隐私文案和当前预览 artifact 命名。非 Windows 静态检查不代表 WinUI 已编译或实机元数据可用。

## 7. 实机放行

Win10 标准用户必须使用真实 Mihomo 连接制造受控 Proxy 流量，并记录四项聚合数字。若主机名或应用识别始终为零，立即停止 W2D-1/W2D-2，不得用目标 IP、节点、规则或猜测进程补位。

W2D-0 通过只证明 Windows 环境存在连接分析元数据，不证明历史归因的覆盖率、性能或隐私门禁已经完成。实际结果由父工作区验收记录收口后，才能进入 W2D-1。
