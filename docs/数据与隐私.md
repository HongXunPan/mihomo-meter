# 数据与隐私

## 原则

Mihomo Meter 采用本地优先、最小采集和明确口径原则。

## MVP-1 保存的数据

- Controller 回环地址
- macOS Data Protection Keychain 中的 Controller Secret

实时分类、连接运行基线、Mihomo 版本和速率窗口只保存在内存中，应用退出后不保留。

以下数据将在 MVP-2 经过独立设计和迁移后才会保存：

- 分钟级 Proxy、DIRECT、REJECT 和未知流量汇总
- 本地统计记录点
- Mihomo 内核会话标识

## 不保存的数据

- Controller Secret 明文
- 订阅地址和访问令牌
- 完整域名或目标 IP
- 进程完整路径
- 单连接长期明细
- 网络内容

Controller Secret 不写入 UserDefaults、日志、测试样例或流量数据；应用只在用户手动提交且验证成功后更新自身 Data Protection Keychain，启动和自动重连不重复写入。工程启用 Keychain Sharing capability 仅用于声明自身 App ID 的默认访问组，不配置跨应用共享组，也不读取或迁移开发阶段遗留的传统文件型 Keychain 条目。

XCTest 宿主不会装配生产监控、访问真实 Keychain 或写入应用诊断日志；凭据持久化语义只通过内存替身和查询结构测试验证。

## Debug 诊断日志

Debug 构建会在应用沙盒中写入本地诊断日志：

```text
~/Library/Containers/com.HongXunPan.MihomoMeter/Data/Library/Logs/MihomoMeter/diagnostics.log
```

诊断日志只记录：

- 应用启动时间、Bundle ID、签名类型和 Team Identifier 是否存在
- Keychain 读取、保存、删除的发起原因、请求标识、开始与完成阶段、结果状态码和耗时
- Mihomo 连接尝试与取消来源、最近快照间隔、重连原因、网络错误代码、退避秒数、成功或终止状态

日志不会记录 Controller Secret、Secret 长度、Controller 地址、节点、请求内容、原始错误文本、完整文件路径或真实响应。日志不上传到任何服务器。单个文件上限为 512 KiB，最多保留当前日志和一份轮换日志，整体上限约 1 MiB；超过 7 天未更新的日志会在下次写入前自动删除。应用停止后也可以直接删除整个 `MihomoMeter` 日志目录。

Release 构建不写入该 Debug 诊断日志。

## 网络行为

- 默认只允许连接 `127.0.0.1` 或 `::1` 上的 Controller。
- 不向项目维护者或第三方上传流量统计。
- 不修改 Mihomo、Clash Verge Rev 或 macOS 网络配置。
- 不读取 Clash Verge 配置文件、Secret 或私有 IPC。

## 统计口径

无法可靠识别出口类型的流量进入未知分类，不会根据节点名称或匹配规则进行猜测。界面将同时展示分类覆盖率，避免把不完整结果描述为计费级精确数据。

MVP-1 不保存今日或总累计，本机实时分类也不等同于机场计费流量。

## 测试数据

公开仓库中的响应样例必须经过脱敏，不得包含真实订阅、节点、域名、IP、进程路径或用户标识。
