# 数据与隐私

## 原则

Mihomo Meter 采用本地优先、最小采集和明确口径原则。

## 保存的数据

- Controller 回环地址
- macOS 登录钥匙串中的 Controller Secret
- 应用沙盒 Application Support 目录中的 SQLite 流量账本
- 分钟级 Proxy、DIRECT、REJECT 和未知分类字节数
- 每日分类汇总、观测时间和本地生成的内核会话 UUID
- 秒表式统计任务的名称、备注、状态、时间和 Proxy 累计基线
- 独立 `quota.sqlite3` 中本地生成的订阅 UUID、轻量模式名称、可选 Profile UID、展示名称和追踪状态
- 指定 Profile 的订阅地址 HMAC-SHA256 指纹和独立观察间隔
- 指定 Profile 的上次和下次查询时间、已查询地址指纹、连续失败数和每日自动重试计数
- 机场返回的 `upload`、`download`、`total`、`expire`、可选源更新时间及其派生剩余量
- 订阅额度周期、用量重置、总额度增减、到期时间变化事件，以及 24 小时、7 天、30 天趋势所需快照
- UserDefaults 中用于恢复用户所选 Profile 目录权限的不透明安全范围书签
- macOS 登录钥匙串中用于计算 Profile 地址指纹的应用本地随机密钥

单连接明细、运行配置摘要、活动规则类型、速率窗口、运行时 Provider 键和原始订阅 URL 只保存在内存中。SQLite 使用 macOS SDK 自带的系统 `SQLite3`，数据库主文件、WAL 和 SHM 均位于应用自身沙盒。当前运行订阅轻量模式不请求用户选择文件或授予外部目录权限；只有指定 Profile 模式需要用户明确选择目录。

## 不保存的数据

- Controller Secret 明文
- 订阅地址和访问令牌
- Mihomo Provider 名称、节点列表和 `/providers/proxies` 完整响应
- 完整域名或目标 IP
- 进程完整路径
- 单连接长期明细
- 规则匹配内容 `rulePayload`
- 网络内容
- 订阅查询响应正文、完整响应头和原始错误文本

Controller Secret 不写入 SQLite、WAL、SHM、UserDefaults、日志、测试样例或流量数据；应用只在用户手动提交且验证成功后更新自身登录钥匙串，启动和自动重连不重复写入。工程不启用 Keychain Sharing、不配置跨应用共享组，也不允许其他应用仅凭已知服务名读取凭据。清除配置时优先删除钥匙串条目；若 macOS 因条目所有权拒绝删除，则覆盖为空值，后续读取按未保存处理。

登录钥匙串的访问控制列表由 macOS Keychain 保存，不在应用目录或仓库中。正式版本使用固定 Bundle ID 与固定自签名证书组成稳定的代码指定要求；后续仍使用同一证书签名的版本可以继续读取已有 Secret。首次从旧 Data Protection Keychain 版本升级时，需要重新填写一次 Secret；替换正式签名证书同样属于需要迁移凭据的破坏性变更。

## Profile 目录权限

指定 Profile 模式通过系统目录选择面板获得用户授权，并只申请“用户所选文件只读”沙盒权限。应用只读取所选目录根部的 `profiles.yaml`，不修改 Clash Verge 配置，也不读取其 Secret、节点文件或私有进程间通信。解析器只接收 `current` 和远程订阅条目的 `uid`、`type`、`name`、`url`，其余字段不会进入应用模型。

安全范围书签只用于重启后恢复同一只读授权，不保存为可展示路径。访问在目录观察期间成对开启和关闭；用户点击“停止访问”后会停止观察、释放安全范围并删除书签。书签失效或目录不可读时，应用要求用户重新选择，不会尝试绕过沙盒权限。

Profile UID 用于保持改名和订阅地址重置前后的本地身份连续性。原始 URL 不写入 UserDefaults、SQLite、日志或用户界面；额度账本只保存以独立 Keychain 随机密钥计算的 HMAC-SHA256 指纹。删除后以新 UID 重新导入的 Profile 会视为新身份，不继承旧历史。

XCTest 宿主不会装配生产监控、访问真实 Keychain 或写入应用诊断日志；凭据持久化语义只通过内存替身和查询结构测试验证。

## 本地诊断日志

Debug 与正式版本都会在应用沙盒中写入本地脱敏诊断日志：

```text
~/Library/Containers/com.HongXunPan.MihomoMeter/Data/Library/Logs/MihomoMeter/diagnostics.log
```

诊断日志只记录：

- 应用启动时间、Bundle ID、签名类型和 Team Identifier 是否存在
- Keychain 读取、保存、删除的发起原因、请求标识、开始与完成阶段、结果状态码和耗时
- Mihomo 连接尝试与取消来源、最近快照间隔、重连原因、网络错误代码、退避秒数、成功或终止状态
- 运行配置摘要读取失败及其固定类型化原因
- 指定 Profile 配额查询的本地请求标识、本地订阅 UUID、12 位地址 HMAC 短指纹、手动或自动触发、是否当前 Profile、代理类型、UA 来源分类、固定结果分类、HTTP 状态或网络错误代码、固定网络原因、配置的超时秒数、耗时和重试间隔

日志不会记录 Controller Secret、Secret 长度、Controller 地址、Profile 名称、Profile 真实 UID、订阅地址、Token、节点、UA 原文、请求内容、原始错误文本、完整响应头、响应正文、完整文件路径或真实连接目标。日志不上传到任何服务器。单个文件上限为 512 KiB，最多保留当前日志和一份轮换日志，整体上限约 1 MiB；超过 7 天未更新的日志会在下次写入前自动删除。

用户可以从应用帮助菜单选择“打开诊断日志文件夹”，复制 `diagnostics.log` 和 `diagnostics.previous.log` 反馈问题。应用停止后也可以直接删除整个 `MihomoMeter` 日志目录；下次发生诊断事件时会重新创建。

## 网络行为

- Controller 连接只允许 `127.0.0.1` 或 `::1`。
- 应用启动及用户手动检查时会通过 Sparkle 请求 GitHub Release 中公开的 `appcast.xml`，不携带 Controller 地址、Secret 或流量数据。
- 只有用户确认安装更新后，Sparkle 才会下载公开的 Universal DMG；应用禁用后台静默安装，也不启用匿名系统画像。
- 不向项目维护者或第三方上传流量统计。
- 不修改 Mihomo、Clash Verge Rev 或 macOS 网络配置。
- 除用户明确授权目录中的 `profiles.yaml` 必要字段外，不读取 Clash Verge 配置文件、Secret 或私有 IPC。
- Controller 校验成功后，应用立即只读请求一次 `/providers/proxies`，随后每 5 分钟请求一次；断开或重连期间停止观察。
- 轻量模式的配额请求只解码必要的更新时间和 `subscriptionInfo` 字段，不调用 Provider 更新接口，也不接触订阅 URL。
- 指定 Profile 模式只对用户已选择的 HTTPS 订阅地址发起请求，请求必须经过当前 Mihomo 暴露的 mixed、HTTP 或 SOCKS 本地代理；代理不可用时等待，不静默直连。
- 指定 Profile 请求使用系统证书校验和 15 秒超时，只跟随 HTTPS 重定向；`User-Agent` 优先复用 Mihomo `global-ua`，否则使用 Mihomo 默认值 `clash.meta`；取得标准 `Subscription-Userinfo` 或兼容的 `*-subscription-userinfo` 元数据响应头后取消正文，不缓存或持久化 UA、正文与完整响应头。
- 自动查询使用全局单并发、0 至 30 秒抖动和每日有限重试；手动查询有 60 秒冷却，避免形成请求风暴。

## 统计口径

无法可靠识别出口类型的流量进入未知分类，不会根据节点名称或匹配规则进行猜测。界面将同时展示分类覆盖率，避免把不完整结果描述为计费级精确数据。秒表式任务只计算 Proxy 本机累计的基线差值，DIRECT 和未知不会静默计入任务结果。

应用未运行期间不补算流量；睡眠或重连后的可确认内核累计差值进入未知分类。正常退出和下次启动恢复都会把遗留任务标记为“已中断”，结束时间取最后一次成功观测时间。

Proxy 流量模块中的“清空本地统计”只会关闭并重建 `traffic.sqlite3`，同时删除全部秒表式统计任务；它不会删除 `quota.sqlite3`，服务地址和访问密钥（Secret）也保持不变。订阅余额模块中的“清空订阅余额数据”会关闭并重建 `quota.sqlite3`，删除订阅身份、Profile 选择、地址指纹、配额快照、周期、变化事件和查询状态；Controller 配置、Profile 目录只读书签与地址指纹 HMAC 密钥保留，用户需要重新选择追踪 Profile。停止 Profile 目录访问只删除书签和停止观察，不删除已经记录的 Profile 身份或额度历史。清除功能不承诺删除已有备份、APFS 快照或底层存储痕迹。本机统计不等同于机场计费流量。

轻量订阅追踪只在 Mihomo 恰好暴露一个有效配额候选、且用户明确确认后记录。零个或多个候选、运行来源变化或 Controller 地址变化会暂停记录；应用不按 Provider 名称、`total` 或 `expire` 猜测和合并历史。Provider 来源键不持久化，因此应用重启后无法利用该键验证来源连续性，也无法可靠感知同一运行来源背后的 Profile 切换。机场配额包含其他设备、线路倍率和机场计费规则，不与本机 Proxy 流量账本做差值对账。

指定 Profile 模式以 Profile UID 确认身份，并允许每个已选 Profile 保存独立查询间隔。该间隔不跟随 Clash Verge 自动刷新周期；原始 URL 只在内存中交给独立调度器，查询状态只持久化时间、地址指纹和失败计数。查询失败保留最近有效快照，不写零值。
