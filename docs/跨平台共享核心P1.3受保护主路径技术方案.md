# 跨平台共享核心 P1.3 受保护主路径技术方案

## 1. 文档定位

- 状态：P1.3-0 设计已锁定，尚未启用共享主路径
- 更新日期：2026-08-11
- 前置门禁：P1.2b 双端运行态验收已通过
- 目标：让共享流量缩放结果分阶段进入生产返回路径，同时保留确定性原生回退

P1.3 只处理字节数、完整速率和紧凑速率三类纯格式化路径，不共享 View、窗口生命周期、网络、Controller 解码、凭据、SQLite、本地化文案或异步调度。Rust 继续只返回固定宽度的缩放数值、单位和小数位，不跨 ABI 返回字符串。

## 2. 受保护主路径契约

平台调用点先生成现行原生文本，再调用共享核心缩放并由 Swift 或 C# 平台适配器渲染共享文本。影子模式始终返回原生文本；受保护主路径仅在共享文本与原生文本完全一致时返回共享文本。ABI 不匹配、动态库调用失败、未知单位、不支持的小数位、文本不一致或其他未知错误，都必须在本次调用内返回原生文本，不得抛到 View、改变监控状态或中断采样。

受保护主路径仍计算原生文本作为一致性护栏，因此切换不会降低 P1.2b 已建立的逐次对照强度。P1.4 是否移除逐次原生护栏属于后续独立决策，不在本阶段删除原生算法。

生产代码不增加用户开关、持久化模式或可远程修改的配置。每个格式是否进入受保护主路径，由对应阶段的源码调用点明确决定；回滚只需把该调用点恢复为影子模式或原生返回，不涉及 ABI、数据迁移或用户配置迁移。

## 3. 路由与诊断

双端新增同语义的路由结果，至少包含最终文本、路由来源和粗粒度状态。路由来源只有 `shared_primary` 与 `native_fallback`；失败状态区分 ABI、原生调用、结果结构、文本不一致和未知失败，不包含输入字节、原生或共享文本、路径、异常详情、Secret 或连接目标。

未切换格式继续使用 `shared_core.traffic_shadow` 事件；已切换格式使用 `shared_core.traffic_route` 事件。正常主路径按格式只记录一次 `result=shared_primary`；原生回退按“格式 + 粗粒度状态”在单次进程内去重。诊断回调失败不得影响最终文本。

启动探针继续验证 ABI 和固定输入，但不作为唯一运行状态开关。每次格式化调用都必须独立具备失败回退能力，避免启动后库状态或单次异常破坏应用展示。

## 4. 分阶段实施

| 阶段 | 交付 | 生产返回路径 | 合并门禁 |
| --- | --- | --- | --- |
| P1.3-0 | 本技术方案与静态契约 | 三类格式仍返回原生文本 | 双端静态契约与 CI |
| P1.3-1 | 双端路由基础设施、注入点和确定性测试 | 三类格式仍为影子模式 | Rust、Swift、C# 单测与双端构建 |
| P1.3-2 | `byte_count` 切换 | 字节数受保护主路径；其余影子 | 统一向量、回退测试、双端 CI |
| P1.3-3 | `rate` 切换 | 字节数与完整速率受保护主路径 | 统一向量、回退测试、双端 CI |
| P1.3-4 | `compact_rate` 切换 | 三类格式均为受保护主路径 | 统一向量、回退测试、双端 CI |
| P1.3-5 | 双端实机验收与状态收口 | 保持三类受保护主路径 | 双端运行态门禁与用户确认 |

每一阶段使用独立分支和 PR；PR 门禁通过后才能合并并进入下一阶段。P1.3-1 至 P1.3-4 不删除原生格式化实现，也不合并额外算法候选。

## 5. 双端实现边界

Swift 与 C# 分别维护轻量平台路由器，复用现有共享核心适配器、平台共享文本渲染器、原生格式化器和诊断去重机制。路由器只负责决策与错误映射，不复制 Rust 缩放算法。调用点继续属于现有领域或展示格式化边界，View 不直接接触 FFI。

双端路由器必须提供可注入的共享缩放闭包或委托，以便测试 ABI 失败、调用失败、未知单位、异常小数位、文本不一致和诊断回调失败。生产默认注入现有 Rust 适配器，不引入第三方依赖、代码生成器或新的包管理步骤。

## 6. 自动化与实机门禁

P1.3-1 的单元测试至少覆盖：完全一致时标记共享主路径、任一共享错误时返回原生文本、文本不一致时返回原生文本、诊断失败不改变返回值，以及影子模式永远返回原生文本。后续每个格式切换阶段必须锁定调用点模式，并保留 P1.2b 统一向量差分。

P1.3-5 要求 macOS 与 Windows 各至少两次独立启动，其中一次为冷启动；每个平台至少连续连接 30 分钟并覆盖“空闲 → 产生流量 → 再次空闲”。三类格式都必须出现一次 `result=shared_primary`，不得出现任何 `native_fallback`、重复诊断失控、展示变化、启动异常或敏感内容。Windows 继续使用 Windows 10 22H2 x64 标准用户和对应 CI 产物，macOS 使用真实设备和生产应用形态。

## 7. 回滚与停止条件

单次调用异常立即自动回退原生文本；某个格式出现非预期回退、性能退化或平台差异时，只回滚该格式的调用点，不撤销其他已通过阶段。发布后需要整体停用时，通过源码回滚三处调用点并重新走 CI，不修改 ABI、数据或用户设置。

出现共享结果未与原生结果完全一致仍被返回、失败越过路由器、诊断包含敏感内容、必须增加用户运行时开关、需要 Rust 返回字符串、原生实现被提前删除、双端阶段无法独立回滚，或任一平台 CI / 实机门禁失败时，立即停止后续阶段并保留最近一个已通过状态。
