# Windows 阶段 W0 实机指南

> 本文是 W0 历史 artifact 的验收说明。W1 预览目录不再包含 `run-w0-gate.cmd`，当前阶段请改用[Windows 阶段 W1 实机指南](Windows阶段W1实机指南.md)。

## 1. 用途与环境

本指南用于验证 Windows W0 壳层，不验证 Mihomo 数据能力。固定环境为 Windows 10 22H2 x64、标准用户、无预装 .NET/Windows App SDK 的普通使用条件；测试产物应来自 W0 对应提交的 Windows CI 自包含目录 artifact。

开始前记录 Windows 版本、CPU 架构、是否标准用户、提交 SHA 和 artifact 名称。不得记录用户名、机器唯一标识、完整本机路径或其他应用的隐私画面。

## 2. 启动与单实例

1. 解压 artifact，在不提升权限的情况下运行 `MihomoMeter.Windows.App.exe`。
2. 确认没有 UAC，主窗口与通知区域图标出现，任务管理器中只有一个应用实例。
3. 再次运行同一入口，确认既有主窗口恢复并前置，没有第二个常驻进程或第二个窗口。
4. 若需要阶段码，从命令提示符运行 `run-w0-gate.cmd`；输出只应包含 `W0_STAGE` 结构化行，不应生成日志文件。

## 3. 窗口与通知区域

1. 点击主窗口系统关闭按钮，确认窗口隐藏但进程和通知区域图标仍在。
2. 依次用通知区域左键、菜单“打开 Mihomo Meter”恢复主窗口，确认始终复用同一窗口。
3. 在任务管理器中重启 Windows Explorer，确认通知区域图标自动恢复且菜单仍可用。
4. 让系统睡眠并恢复，确认没有重复图标、窗口或进程。

## 4. 悬浮入口

1. 通过通知区域菜单开启悬浮图标，确认它不出现在任务栏和 Alt+Tab 中，也不持续抢占焦点。
2. 单击悬浮图标，确认既有主窗口恢复并前置。
3. 将悬浮图标拖到同一显示器边缘，再隐藏并显示，确认当前进程内保持位置且不会越过可用区域。
4. 如有多显示器，将它跨屏拖动，并在 100%、150%、200% DPI 组合下检查尺寸、点击和位置校正。
5. 明确退出应用后重新启动，确认悬浮图标使用默认位置；W0 不持久化开关或位置。
6. 关闭悬浮图标，确认只销毁悬浮窗口，通知区域与主进程继续运行。

## 5. 明确退出与资源记录

1. 从通知区域菜单选择“退出”。
2. 确认主窗口、悬浮入口、通知区域图标和应用进程全部消失，没有残留窗口。
3. 重新启动后空闲五分钟，记录任务管理器显示的平均 CPU 与内存工作集；CPU 目标低于 1%，内存只如实记录，不用未经对照的阈值判定。
4. 确认应用目录及用户目录没有由 W0 主动生成的日志、数据库、配置或诊断压缩包。

## 6. 结果记录

每项记录“通过 / 失败 / 未覆盖”。失败时只记录场景、可复现步骤、`W0_STAGE` 阶段码和必要的脱敏现象；不要提交完整终端日志或机器路径。任一必测项失败都不得宣称 W0 通过，也不得用 Windows 11、管理员运行或 CI 构建代替。
