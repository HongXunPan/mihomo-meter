# Windows 阶段 W2B 实机指南

## 1. 用途与阶段边界

本文用于 Windows 10 22H2 x64 标准用户环境下的 W2B 滚动验收。W2B 分为账本与领域、完整工作台、通知区域与生命周期三个增量；只测试目标 artifact 已经公开的能力，不用后续条目否定前一增量的自动化结果。

W2B1 只交付 schema v2 与任务领域，W2B2 增加完整工作台且已完成滚动实机验收，W2B3 增加通知区域原生任务子菜单与生命周期收口。GitHub Actions 不能替代数据库升级、系统菜单、窗口生命周期和真实 Controller 实机反馈。

## 2. 准备与升级

1. 从目标提交的“Windows 构建与测试”工作流下载 `mihomo-meter-windows-w2b-x64-<提交>` artifact 并完整解压。
2. 记录提交 SHA、工作流链接、Windows 版本和 Mihomo 版本；始终使用标准用户运行。
3. 优先使用已完成 W2A 测试且不包含敏感明细的现有 `traffic.sqlite3` 验证 v1→v2。不要回传数据库、WAL、SHM、Secret、Controller 地址或真实响应。
4. 升级前从通知区域明确退出，确认没有 Mihomo Meter 进程；不要在进程占用数据库时复制、删除或替换账本。
5. 启动 W2B artifact 后确认 W2A 今日与历史累计仍存在，实时 Proxy、DIRECT、REJECT、未知分类继续变化且没有明显重复。

升级后累计丢失、数据库被重建、必须管理员运行、出现第二份 `e_sqlite3.dll` 或实时监控因迁移失败停止时，立即结束测试并保留现状，不反复删除数据库规避问题。

## 3. W2B1 账本与领域

W2B1 的任务 CRUD、重叠基线、结束原因、恢复、30 日补零、清空事务和迁移回滚由 Core 单元测试验证；当前没有 UI 时，不要求测试者使用 SQLite 工具手工写任务表，也不得通过修改 `PRAGMA user_version` 冒充升级验收。

实机只检查：W2A 数据库可正常升级；升级后实时与累计继续；应用重启不重复；Mihomo 重启不清空历史；数据库仍只包含分类聚合、会话、运行状态和统计任务基线，不包含连接、节点、目标、规则、地址或 Secret。

## 4. W2B2 完整工作台

包含 W2B2 工作台的 artifact 执行：

1. 在“实时监控”和“Proxy 流量”之间反复切换，确认复用同一主窗口且内容铺满可用宽度，右侧没有无语义空白；实时值不会因切页或刷新先闪成 `--`，再跳回实际值。
2. 并行开始两个任务，分别制造 Proxy 流量并在不同时间停止，确认两个结果独立且只包含 Proxy 上传、下载和合计。
3. 使用自定义名称和备注新建任务，验证首尾空白被规范化，空名称不能提交。
4. 验证进行中、历史记录和全部筛选；高频刷新时任务容器不整行闪烁，已结束任务保持稳定，进行中任务只更新真实变化的持续时间与流量文字；重命名、删除单个任务不改变今日或历史累计。
5. 最近 30 日包含今日并按本地日期排列；X 轴显示稀疏日期，Y 轴显示字节刻度和网格线；无流量日保留柱位，不制造插值；范围合计、峰值日和每柱可访问名称与账本值一致。
6. 关闭主窗口后任务继续；Mihomo 自动重连或计数器回退不结束任务。
7. 清空前必须出现明确范围确认；取消不改变数据，确认后累计、任务和图表归零，但 Controller 地址、Credential Manager Secret 与悬浮图标设置保留。

## 5. W2B3 通知区域与生命周期

包含 W2B3 通知区域任务菜单的 artifact 执行：

1. “统计任务”显示全部活动数量，并始终保留五个任务槽位；活动任务优先，再用本地今日已完成或已中断任务补足。
2. 建立超过五个候选任务，确认排序稳定、溢出入口打开既有工作台，不创建第二个窗口。
3. 展开每个已占用槽位，确认原生子菜单显示下载、上传、合计与时间；活动槽位的“查看任务”和“停止任务”不会误触混淆。
4. 从“查看任务”或溢出入口进入既有主窗口的“Proxy 流量”，不创建第二个窗口；命令执行后菜单按 Windows 语义关闭，不立即重开或显示自绘面板。
5. 关闭普通窗口只隐藏且不结束任务；用户断开监控后任务标记为已中断。
6. 从通知区域明确退出后任务以最后成功观测中断；强制结束进程后再次启动，遗留任务以恢复原因中断。
7. 单实例、Explorer 恢复、悬浮图标、高 DPI、多显示器、睡眠恢复和明确退出不出现重复窗口、图标、WebSocket 或进程。
