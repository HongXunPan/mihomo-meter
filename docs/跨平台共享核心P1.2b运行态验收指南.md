# 跨平台共享核心 P1.2b 运行态验收指南

## 1. 文档定位

- 状态：待双端实机执行
- 适用范围：P1.2b 字节数、完整速率和紧凑速率生产影子比较
- 放行目标：为是否进入 P1.3 主路径评估提供正向运行证据

本指南只验证共享核心生产影子路径确实执行、结果与原生算法一致且不影响原生输出，不替代完整功能回归、发布验收或长期稳定性观察。P1.2b 通过后也不得自动切换共享核心主路径。

## 2. 前置条件与证据边界

1. 目标构建必须包含首次 `matched` 正向诊断能力，并记录完整 commit；对应 macOS 与 Windows CI 必须通过。
2. macOS 与 Windows 分别执行至少两次独立启动，其中一次为冷启动；每个平台至少保持一次连续连接 30 分钟，并覆盖“空闲 → 产生流量 → 再次空闲”。
3. 只记录平台、系统版本、构建 commit、起止时间、场景结论和下列粗粒度事件。不得把完整诊断日志、Controller Secret、订阅地址、节点、路径、连接目标或真实响应写入验收记录。
4. Windows 必须使用 Windows 10 22H2 x64 标准用户；macOS 使用项目当前支持的真实设备和生产应用形态。CI、虚拟静态检查或控制台“构建成功”不能替代实机证据。

## 3. 三类格式场景

| 格式 | macOS 触发场景 | Windows 触发场景 | 正向事件 |
| --- | --- | --- | --- |
| `byte_count` | 打开流量统计或连接分析，确认累计流量出现 | 打开 Proxy 流量或连接分析，确认累计流量出现 | `result=matched` |
| `rate` | 连接 Mihomo 后查看分类速率或运行详情 | 打开主窗口分类速率或实时连接 | `result=matched` |
| `compact_rate` | 查看状态菜单连接列表中的紧凑速率 | 查看通知区提示或悬浮窗速率 | `result=matched` |

每个场景都应确认界面继续使用现行十进制 1000 进位和 macOS 精度口径。正向事件只证明对应生产路径执行且本次比较一致，不证明其他功能已完成验收。

## 4. macOS 验收

1. 启动目标构建并完成 Mihomo 连接，依次覆盖三类格式场景；退出后重新启动并至少再次覆盖三类场景一次。
2. 通过帮助菜单打开诊断日志目录，或读取应用沙盒内 `Library/Logs/MihomoMeter/diagnostics.log`。只核对事件类型，不复制完整日志。
3. 每次进程至少应出现：

```text
event=shared_core.runtime_probe result=ready
event=shared_core.traffic_shadow format=byte_count result=matched
event=shared_core.traffic_shadow format=rate result=matched
event=shared_core.traffic_shadow format=compact_rate result=matched
```

4. 同一进程中每个 `format + result` 组合只能出现一次。不得出现 `abi_mismatch`、`native_call_failed`、`unsupported_traffic_unit`、`unexpected_result`、`mismatch` 或 `unknown_failure`。

## 5. Windows 验收

从 Windows CI 对应构建产物目录以标准用户启动，并显式打开限量启动控制台：

```powershell
$env:MIHOMO_METER_STARTUP_CONSOLE = "1"
.\MihomoMeter.Windows.App.exe
```

连接 Mihomo 后依次覆盖三类格式场景，保持一次连续连接 30 分钟，再退出并重新启动复验。每次进程至少应出现：

```text
WINDOWS_STAGE stage=shared_core_runtime_ready
WINDOWS_DIAGNOSTIC event=shared_core.traffic_shadow format=byte_count result=matched
WINDOWS_DIAGNOSTIC event=shared_core.traffic_shadow format=rate result=matched
WINDOWS_DIAGNOSTIC event=shared_core.traffic_shadow format=compact_rate result=matched
```

同一进程中每个 `format + result` 组合只能出现一次。不得出现 `abi_mismatch`、`native_call_failed`、`unexpected_result`、`mismatch`、`unknown_failure` 或对应 `WINDOWS_FAILURE`。

## 6. 放行与停止条件

只有双端两次独立启动都获得三类 `matched`、启动探针为 `ready`、连续连接期间无异常事件且现行展示未变化，P1.2b 运行态门禁才通过。缺少任一正向事件属于证据不完整，不得按“未发现异常”放行。

出现非 `matched` 状态、重复日志失控、原生展示变化、启动或连接受影响、诊断包含敏感信息，或 Windows 不是标准用户真实 Win10 22H2 x64 环境时，立即停止 P1.3，保留原生主路径并回到对应实现或环境问题定位。

## 7. 验收记录模板

```text
平台 / 系统版本：
构建 commit：
执行时间段：
启动次数：
连续连接时长：
byte_count matched：通过 / 未通过
rate matched：通过 / 未通过
compact_rate matched：通过 / 未通过

```

验收记录未明确为“双端通过”前，`docs/跨平台共享核心技术方案.md` 必须继续保持 P1.2b 状态，P1.3 只能作为待评估阶段。
