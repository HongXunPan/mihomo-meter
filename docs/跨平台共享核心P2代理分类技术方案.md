# 跨平台共享核心 P2 代理分类技术方案

## 1. 文档定位

- 状态：P2-2 双端生产影子已实现，生产结果仍由原生分类决定
- 更新日期：2026-08-12
- 平台基准：修正数字归一化后的 macOS `ProxyClassifier`
- 目标：共享原始代理类型到 Proxy、DIRECT、REJECT 的纯分类规则

P2 只共享 `/proxies` 目录已经命中的原始类型字符串分类。链叶选择、目录查找、空链与目录缺项原因、目录刷新、连接增量、速率、账本、网络、持久化、凭据和 View 继续留在平台层。节点名称、完整代理链、目标、规则和真实连接数据不得进入共享核心。

P2-F0 已先修正双端原生基线：归一化同时保留字母与数字，并用完整现行协议矩阵确认 `Socks5`、`Hysteria2` 等类型均归为 Proxy。P2 后续以该行为为唯一迁移基准，不把旧缺陷固化为共享契约。

## 2. 共享边界与分类契约

共享输入是目录返回的原始类型 UTF-8 字节，不是入口协议、节点名或链路。平台仍读取 `chains.first` 作为已实测叶子，并完成精确、区分大小写的目录查找；只有查到原始类型后才调用共享分类。

共享核心只接受不超过 64 字节的 ASCII 输入。归一化固定执行 ASCII 小写，并删除字母和数字以外的字符；空值、非 ASCII、超长或无效空指针组合不得猜测。现行具体代理类型为 `anytls`、`http`、`hysteria`、`hysteria2`、`shadowsocks`、`shadowsocksr`、`snell`、`socks5`、`ssh`、`trojan`、`tuic`、`vless`、`vmess`、`wireguard`。

稳定分类值固定为：

| 值 | 结果 | 平台语义 |
| ---: | --- | --- |
| 0 | `unrecognized` | 不直接映射未知，必须执行原生回退 |
| 1 | `proxy` | 具体代理协议 |
| 2 | `direct` | `Direct` |
| 3 | `reject` | `Reject` 或 `RejectDrop` |

`unrecognized` 不是共享成功。即使当前原生实现也会判为未知，生产路径仍必须回退原生分类，保证 Mihomo 新增协议后平台可以先兼容而不被旧共享核心覆盖。平台把原生未知继续映射为 `ambiguousProxyType`；空链和目录缺项仍分别保留 `emptyChain` 与 `missingCatalogEntry`。

## 3. ABI 与适配器

P2-1 已追加 `mm_classify_proxy_type(const uint8_t *input, uint32_t length, mm_proxy_type_classification_t *output)`，不提升现有 ABI 主版本。输出结构只含一个 `uint32_t category`；成功返回 `0`，空输出指针返回 `-1`，非零长度配合空输入指针或非 ASCII 返回 `-2`，超长输入返回 `-3`。长度为零时允许输入指针为空并返回 `unrecognized`。C ABI 无法验证任意悬空地址，调用方仍必须保证非空输入和输出指针分别指向足长可读与完整可写空间。

Rust 不持有输入指针、不分配跨边界内存，不让 panic、引用、字符串或异常越过 C ABI。Swift 与 C# 适配器只负责 UTF-8 缓冲区、长度检查、枚举验证和粗粒度错误映射，不复制分类表。任何适配器、ABI、加载或未知错误都必须立即回退原生实现。

统一向量使用独立 `proxy_type_classification.json`，覆盖现行协议、大小写、空格、连字符、下划线、数字、空值、策略组、新类型、非 ASCII 和 64/65 字节边界。macOS 探针和 Windows 核心测试均直接读取该文件，让共享适配器与原生 `ProxyClassifier` 差分；Rust 单元测试另外覆盖空指针和错误码。向量不得包含真实节点、订阅、连接或响应数据。

## 4. 路由、诊断与隐私

P2 使用独立代理分类路由，不扩展流量格式化路由的职责。平台 `ProxyClassifier` 先完成链叶、目录和原生分类，再把“原始类型 + 原生分类”交给注入的解析闭包；没有命中目录时不会调用共享核心。领域对象默认闭包直接返回原生分类，只有 macOS `TrafficMonitoringRun` 与 Windows `TrafficMonitoringStream` 的生产装配显式注入 P2 Shadow，因此移除该装配即可单点回滚。

影子和受保护阶段会计算原生分类；懒回退阶段先调用共享核心，只有 `proxy`、`direct` 或 `reject` 才视为共享成功。`unrecognized`、ABI 不匹配、原生调用失败、非法结果、输入不支持或未知异常必须且只能执行一次原生闭包。

P2-2 Router 将共享 `proxy`、`direct`、`reject` 转回平台分类做精确差分；共享 `unrecognized` 只有在原生也是 `ambiguousProxyType` 时标为 `unrecognized`，否则标为 `mismatch`。适配器和加载错误转换为 `abi_mismatch`、`native_call_failed`、`unsupported_input`、`input_too_long`、`unexpected_result` 或 `unknown_failure`。无论状态为何，Shadow 都返回调用前已得到的原生分类。

诊断只允许记录 `source` 与粗粒度 `status`，按“来源 + 状态”在单进程内去重。来源只使用 `shared_shadow` 或 `native_fallback`；不得记录原始类型、节点名、链路、输入长度、分类前后文本、Secret、地址或异常详情。macOS 进入既有容量与保留期受限的诊断日志；Windows 只进入显式启用的启动控制台。诊断失败不得改变分类结果或追加原生计算。

P2-3 双端实机步骤与证据模板由[运行态验收指南](跨平台共享核心P2-3运行态验收指南.md)持有，本方案只维护阶段门禁摘要。

## 5. 分阶段实施

| 阶段 | 交付 | 生产结果 | 门禁 |
| --- | --- | --- | --- |
| P2-F0 | 双端原生数字归一化与协议矩阵 | 原生 | PR 与 main 双端 CI |
| P2-0 | 本方案与静态契约 | 原生 | 文档、静态契约与双端 CI |
| P2-1（已完成） | Rust ABI、双端适配器、统一向量 | 原生 | Rust、适配器差分与双端 CI |
| P2-2（已完成） | 独立路由、注入边界与生产影子 | 原生 | 路由、诊断、差分与双端 CI |
| P2-3 | 双端影子实机验收 | 原生 | 用户确认运行态门禁 |
| P2-4 | 受保护主路径 | 精确一致才返回共享分类 | 回退测试与双端 CI |
| P2-5 | 双端受保护路径验收 | 受保护主路径 | 用户确认运行态门禁 |
| P2-6 | 共享优先、原生懒回退 | 识别成功走共享，其余原生 | 闭包次数、差分与双端 CI |
| P2-7 | 最终双端验收与收口 | 共享优先、原生懒回退 | 用户确认运行态门禁 |

每个代码阶段使用独立分支和 PR，PR 与合并后的 `main` 双端 CI 都通过后才能继续。P2-1 不得接入生产；P2-2 不得改变生产结果；P2-4 不得停止逐次原生比较；P2-6 不得删除原生分类、受保护路由或确定性差分测试。

## 6. 自动化与实机门禁

自动化必须验证：全部统一向量与双端原生分类一致；具体协议、DIRECT 和 REJECT 输出稳定；未识别类型不被当作共享成功；错误分类值、ABI、输入和加载失败都回退；影子始终返回原生；受保护路径只在一致时返回共享；懒成功不求值原生闭包，所有失败恰好求值一次；诊断去重且失败不影响结果。

P2-3、P2-5 与 P2-7 均要求 macOS 和 Windows 各至少两次独立启动，其中一次冷启动；每个平台至少连续连接 30 分钟，覆盖明确 Proxy 与 DIRECT 流量以及空闲切换。必须观察对应阶段的成功事件，不得出现 mismatch、失败失控、敏感内容、Proxy/DIRECT/REJECT/未知口径变化、账本异常、连接异常或明显 CPU、内存、唤醒退化。REJECT、未知和全部协议矩阵由确定性测试强制覆盖；实机中若自然出现，也必须保持一致。

## 7. 回滚与停止条件

P2-2 回滚为移除影子解析闭包装配；P2-4 和 P2-6 回滚为把同一装配恢复到上一阶段，不修改 ABI、数据库、用户设置或 View。原生 `ProxyClassifier`、完整协议测试和共享差分测试在 P2 完成后仍保留。

出现以下任一情况立即停止并重新规划：共享核心需要接触节点名、代理链或连接数据；`unrecognized` 绕过原生回退；共享错误可能越过路由器；输入长度或指针无法安全约束；热路径出现明显性能退化；DIRECT、REJECT 或未知被并入 Proxy；分类差异可能写入账本；必须引入新依赖、运行时用户开关或远程配置；任一平台 CI 或实机门禁失败。
