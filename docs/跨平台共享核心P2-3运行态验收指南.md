# 跨平台共享核心 P2-3 运行态验收指南

## 1. 文档定位

- 状态：待双端实机验收
- 适用范围：P2-2 原生结果不变的代理类型生产影子
- 目标：确认共享分类实际执行、与原生分类一致且不影响连接、分类和账本

本指南只验证 P2-3 运行态门禁，不替代发布、更新、窗口或完整功能回归。自动化已覆盖 14 种现行代理协议、DIRECT、REJECT、未知、非 ASCII 与输入边界；实机必须覆盖明确的 Proxy、DIRECT 与空闲切换，REJECT 和未知若自然出现也必须保持原有口径。

## 2. 前置条件与证据边界

1. 使用 P2-2 合并后的同一 `main` commit；对应通用 CI 与 Windows CI 必须通过。
2. macOS 和 Windows 各执行至少两次独立启动，其中一次为应用完全退出后的冷启动；每个平台至少一次连续连接 30 分钟。
3. Windows 使用 Windows 10 22H2 x64 标准用户并从该 commit 的 CI 产物启动；macOS 使用源码仓 `scripts/build-debug.sh` 前台启动。
4. 只记录平台、系统版本、构建 commit、起止时间、启动次数、场景结论和粗粒度 `source + status`。不得复制完整日志，不得记录原始代理类型、节点、链路、Controller 地址、Secret、订阅或真实连接目标。

## 3. 场景与界面核对

每个平台每次启动依次执行：连接后保持空闲；产生明确经过代理节点的流量；产生可由当前规则明确判为 DIRECT 的流量；再次空闲。至少一次启动持续 30 分钟，期间核对：

- Proxy、DIRECT、REJECT 和未知仍分开，Proxy 与 DIRECT 速率及累计流量方向合理；
- 实时连接、流量统计和连接分析没有跳类、负增量或异常清零；
- 目录刷新、断开重连和空闲恢复保持原行为；
- 无明显 CPU、内存、唤醒或界面响应退化。

日志中的一次 `matched` 只证明至少一次共享候选与原生分类一致；Proxy 与 DIRECT 的分别覆盖必须同时用可控场景和界面结果确认，不能仅凭去重后的日志代替。

## 4. macOS 验收

在源码仓根目录以前台方式启动，应用退出后命令才返回：

```bash
sh scripts/build-debug.sh
```

通过帮助菜单打开诊断日志目录，或只筛选：

```bash
grep 'event=shared_core.proxy_type_shadow' \
  "$HOME/Library/Containers/com.HongXunPan.MihomoMeter/Data/Library/Logs/MihomoMeter/diagnostics.log"
```

每个进程至少应出现一次：

```text
event=shared_core.proxy_type_shadow source=shared_shadow status=matched
```

同一进程每个 `source + status` 组合最多出现一次。若自然出现共享未识别且原生仍为未知，允许一次 `source=native_fallback status=unrecognized`，但界面未知口径必须不变。不得出现 `abi_mismatch`、`native_call_failed`、`unsupported_input`、`input_too_long`、`unexpected_result`、`mismatch` 或 `unknown_failure`。

## 5. Windows 验收

下载同一 commit 的 Windows CI 预览产物，以标准用户在 PowerShell 中启用限量诊断控制台后启动：

```powershell
$env:MIHOMO_METER_STARTUP_CONSOLE = "1"
.\MihomoMeter.Windows.App.exe
```

每个进程至少应出现：

```text
WINDOWS_STAGE stage=shared_core_runtime_ready
WINDOWS_DIAGNOSTIC event=shared_core.proxy_type_shadow source=shared_shadow status=matched
```

同一进程每个 `source + status` 组合最多出现一次。自然出现 `native_fallback + unrecognized` 时按 macOS 同一规则核对未知口径。不得出现其他失败状态、对应 `WINDOWS_FAILURE`、标准用户启动异常或 DLL 加载失败。

## 6. 放行与停止条件

只有双端都满足“两次启动 + 一次连续 30 分钟 + Proxy/DIRECT/空闲切换 + 至少一次 matched + 无禁止状态 + 现有分类和账本不变”，P2-3 才能通过。缺少正向事件属于证据不完整，不能按“未发现异常”放行。

出现 `mismatch`、共享失败失控、重复诊断、敏感内容、Proxy/DIRECT/REJECT/未知口径变化、账本异常、连接异常或明显资源退化时立即停止；不得进入 P2-4，保留原生结果主路径并回到对应平台定位。
