# MVP-1 使用与统计口径

## 使用前提

Mihomo Meter 依赖 Mihomo 的公开 External Controller API。使用前需在用户自己的 Mihomo 或 Clash Verge 设置中启用 Controller，并由用户手动取得地址和 Secret。

MVP-1 只接受以下回环地址：

- `127.0.0.1:端口`
- `http://127.0.0.1:端口`
- `http://[::1]:端口`

应用不会读取 Clash Verge 配置文件，也不会通过私有 IPC 获取 Secret。

## 首次连接

1. 点击 macOS 状态栏中的 Mihomo Meter。
2. 填写 Controller 地址。
3. 填写 Secret；Controller 未启用鉴权时可以留空。
4. 点击“连接”。

应用先调用 `/version` 验证连接和鉴权，再读取 `/proxies`。两步成功后，地址写入应用设置，Secret 写入本应用的 macOS Keychain，随后建立 `/connections?interval=500` WebSocket。

## 实时统计口径

### 分类

每个活动连接使用 `chains.first` 作为已验证的叶子出口候选，再通过 `/proxies.type` 分类：

- 具体代理协议：Proxy
- `Direct`：DIRECT
- `Reject` 或 `RejectDrop`：REJECT
- 链为空、目录缺失、策略组或类型不明确：未知

应用不会根据节点名称、匹配规则或外层策略组猜测分类。链式代理的业务字节只累计一次。

### 增量

首份连接快照只建立基线。后续按连接 ID 计算上传和下载计数的非负增量；首次出现的新连接从零计算，计数回退时重新建立该连接基线。

活动连接可能在两个快照之间创建并结束。此类无法取得连接链的流量通过内核总增量残差进入未知：

```text
已分类 = Proxy + DIRECT + REJECT
未知 = max(内核总增量 - 已分类, 0)
分类可信度 = 已分类 / 内核总增量
```

### 速率

- WebSocket 请求间隔：500 毫秒
- 原始窗口：按单调时钟聚合的完整 1 秒窗口
- 默认展示：最近两个完整 1 秒窗口的简单平均
- 诊断区：当前原始 1 秒 Proxy 速度

状态栏只展示 Proxy 下载和上传速度；弹层同时展示 DIRECT、REJECT、未知、分类可信度和当前可确认的 Proxy 叶子。

分类可信度低于 95% 时，弹层会明确提示当前结果不适合用于精确判断。该提示不修改 Proxy、DIRECT、REJECT 或未知的原始统计值。

## 断线和异常

- 超过 2 秒没有新快照：实时速度归零并标记数据超时。
- WebSocket 中断：按 `1、2、4、8、16、30` 秒上限退避重连。
- 鉴权失败：停止自动重试，等待用户修正 Secret。
- 响应结构不兼容：停止自动重试并显示错误。
- Controller 或连接计数回退：丢弃旧运行基线，避免负增量。
- 出现代理目录中不存在的新叶子：后台定向刷新一次 `/proxies`，不阻塞 WebSocket。

## MVP-1 边界

MVP-1 只提供当前实时速度，不提供：

- 今日或总累计
- 手动统计记录点
- 应用重启后的恢复
- 机场订阅余额走势
- 本机统计与机场计费的强一致对账

这些能力分别属于后续 MVP-2 和订阅余额阶段。
