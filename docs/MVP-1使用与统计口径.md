# MVP-1 使用与统计口径

## 使用前提

Mihomo Meter 依赖 Mihomo 的公开 External Controller API。使用前需在用户自己的 Mihomo 或 Clash Verge 设置中启用 Controller，并由用户手动取得地址和 Secret。

MVP-1 只接受以下回环地址：

- `127.0.0.1:端口`
- `http://127.0.0.1:端口`
- `http://[::1]:端口`

应用不会读取 Clash Verge 配置文件，也不会通过私有 IPC 获取 Secret。

## 首次连接

1. 点击 macOS 状态栏中的 Mihomo Meter。
2. 展开“Mihomo 连接”，填写服务地址。
3. 填写访问密钥；Mihomo 未启用鉴权时可以留空。
4. 点击“连接”。

应用先调用 `/version` 验证连接和鉴权，再读取 `/proxies` 和 `/configs`。用户手动提交的配置验证成功后，地址写入应用设置，Secret 写入本应用的 macOS 登录钥匙串，随后建立 `/connections?interval=500` WebSocket。应用启动和自动重连会复用已加载的 Secret，不重复写入 Keychain。`/configs` 只用于运行摘要，读取失败不会阻断实时流量。

### 凭据存储与开发签名

登录钥匙串由 macOS 保存访问控制列表。正式版本固定使用 Bundle ID `com.HongXunPan.MihomoMeter` 和自签名证书 `Mihomo Meter By HongXunPan` 组成代码指定要求；同一证书签署的后续版本可以继续读取已有 Secret，正常升级不需要再次授权。

旧版使用 Data Protection Keychain，正式切换到登录钥匙串后的首个版本无法静默读取旧条目，需要用户重新填写一次 Secret。开发构建应通过被 Git 忽略的 `Config.local.xcconfig` 提供自己的 `DEVELOPMENT_TEAM`，不要把个人 Team ID 写入 Xcode 工程文件；开发签名与正式自签名证书属于不同身份，切换时可能需要钥匙串授权或重新填写。

Debug 与正式版本都会生成不含 Secret 的本地脱敏诊断日志，具体位置、字段、用户反馈入口和清理方式见[数据与隐私](数据与隐私.md#本地诊断日志)。

### 版本与更新

连接设置窗口展示 `CFBundleShortVersionString`。应用使用 Sparkle 读取 GitHub 最新 Release 中的 `appcast.xml`，启动时检查一次，也允许用户通过快速菜单原生“检查更新”动作手动触发。发现更新后由 Sparkle 标准界面展示发布信息，只有用户确认后才下载 Universal DMG，并在解压前校验 Ed25519 签名，再替换应用和重启；应用不允许后台静默安装。

`0.1.x` 没有内置 Sparkle，因此首次升级到 `0.2.x` 仍需从 GitHub Releases 手动下载 DMG。安装了包含 Sparkle 的版本后，后续版本才能使用应用内更新。更新检查或下载失败不会影响 Mihomo 监控。

## 实时统计口径

### 分类

每个活动连接使用 `chains.first` 作为已验证的叶子出口候选，再通过 `/proxies.type` 分类：

- 具体代理协议：Proxy
- `Direct`：DIRECT
- `Reject` 或 `RejectDrop`：REJECT
- 链为空、目录缺失、策略组或类型不明确：未知

应用不会根据节点名称、匹配规则或外层策略组猜测分类。链式代理的业务字节只累计一次。

### 增量

首份连接快照只建立基线。后续按连接 ID 计算上传和下载计数的非负增量；首次出现的新连接从零计算，计数回退时重新建立该连接基线。

活动连接可能在两个快照之间创建并结束。此类无法取得连接链的流量通过内核总增量残差进入未知：

```text
已分类 = Proxy + DIRECT + REJECT
未知 = max(内核总增量 - 已分类, 0)
分类可信度 = 已分类 / 内核总增量
```

### 速率

- WebSocket 请求间隔：500 毫秒
- 原始窗口：按单调时钟聚合的完整 1 秒窗口
- 默认展示：最近两个完整 1 秒窗口的简单平均
- 诊断区：当前原始 1 秒 Proxy 速度

连接正常时，状态栏展示 Proxy 下载和上传速度，快速菜单顶部在收到实时观测后显示“刚刚更新”；未连接、连接中、重连、数据超时、鉴权失败或响应不兼容时，改为展示明确状态，不以 `0 B/s` 代替异常。快速菜单以标准父菜单项显示活动连接数量、分类可信度和路由状态摘要，进入相应系统子菜单后查看只读详情。

快速菜单提供“活动 Proxy Top 5”和“活动直连 Top 5”两个原生子菜单，主菜单右侧摘要显示活跃数量或“暂无传输”。子菜单按上传与下载速率之和排序，固定保留五个自然行高槽位，零至五条连接变化不会改变子菜单尺寸；每项展示主机名、应用、双向速度和连接累计，连接消失后立即移除。完整统计窗口在“Proxy 流量 → 实时连接”先切换 Proxy 或直连，再按连接、应用或域名查看并搜索应用与主机名。两类连接分别使用同一 1 秒窗口和最近两个窗口平均；分组累计只合并当前仍活动的连接，不代表历史归因流量。

“分类状态”主菜单摘要显示覆盖率，子菜单显示覆盖率说明以及 DIRECT、REJECT 和未知流量的上下行速度。分类可信度低于 95% 时使用警告色，并明确说明当前结果不适合用于精确判断；提示不修改 Proxy、DIRECT、REJECT 或未知的原始统计值。

### 路由与运行状态

“路由状态”主菜单摘要显示当前出口和运行方式，进入系统子菜单后显示：

- 当前可确认的实际 Proxy 叶子出口
- `Rule`、`Global` 或 `Direct` 运行模式与 TUN 开关
- 当前活动连接命中的规则类型

同一子菜单继续显示原始一秒 Proxy 速度、TUN Stack、自动路由、IPv6、局域网访问、Mixed Port 和 Mihomo 版本。多个出口或规则类型只显示紧凑摘要，悬停可查看完整内存值。

规则展示只使用 `/connections.rule` 的类型，不读取或展示 `rulePayload`。连接分析通过独立适配边界读取 `host`、`sniffHost`、`process` 和 `processPath`：主机名不得用 IP 补位；应用名优先从 `processPath` 最外层 `.app` 容器取得，再降级到 `process` 或路径文件名，完整路径立即丢弃。运行摘要、活动规则类型和实时连接明细只保存在内存中。

活动连接、分类状态和路由状态的父项属于标准 `NSMenuItem`，支持系统悬停、方向键和子菜单避让语义；子菜单内的 SwiftUI 固定详情只读展示，不加入 `Tab` 焦点循环。页头、原生入口、Proxy 统计、订阅余额和底部命令按同一菜单项流排列，不在摘要内建立嵌套滚动区；整体超过屏幕可用高度时由 macOS 统一滚动。快速菜单首次展开不会自动聚焦自定义内容；底部设置、帮助、检查更新和退出等标准菜单命令继续使用系统方向键导航、回车和快捷键。

## 断线和异常

- 超过 2 秒没有新快照：实时速度归零并标记数据超时，但暂不取消 WebSocket；若 5 秒内恢复，继续复用原连接。
- 持续 5 秒没有新快照：使旧流失效并取消 WebSocket，旧流之后到达的迟到快照会被忽略。
- WebSocket 中断：按 `1、2、4、8、16、30` 秒上限退避重连；连接连续稳定 30 秒后，下一次中断从 1 秒重新开始。等待期间可以点击固定顶部区域中的“立即重连”取消当前退避。
- 鉴权失败：停止自动重试，等待用户修正 Secret。
- 响应结构不兼容：停止自动重试并显示错误。
- Controller 或连接计数回退：丢弃旧运行基线，避免负增量。
- 出现代理目录中不存在的新叶子：后台定向刷新一次 `/proxies`，不阻塞 WebSocket。
- `/configs` 读取失败：继续建立实时流，运行方式和详情显示为不可用。

连接元数据覆盖率与 Proxy/DIRECT 实时连接在数据过期、重连、停止监控或内核计数重置时清空。阶段 3.0 实机门禁已通过：46 条 Proxy 样本中主机名识别率 100%，应用识别率 82.6%；未识别应用明确显示为“未知应用”。Proxy 实时页只读展示 `/configs.find-process-mode` 和本次会话应用识别数量；直连页只说明实时、非持久化边界，不将当前连接命中率伪装成会话覆盖率，也不会自动修改 Mihomo 配置。

## 连接历史归因

连接历史默认关闭。用户在“连接分析”明确开启后，应用才会按本地自然日保存“应用名称 × 完整主机名”的 Proxy 上传、下载聚合。缺失字段进入“未知应用”或“未知域名”；记录保留 30 天，每日最多 5,000 个组合，超出汇入“其他”。关闭开关会先刷新最多 10 秒的内存待写数据，再停止新增，已有历史继续可见。

历史页固定补齐最近 30 个本地自然日，选择日期后可查看应用榜、域名榜和交叉筛选，并按字节展示归因记录覆盖率、主机名覆盖率、应用覆盖率和完整归因覆盖率。归因记录覆盖率使用“归因账本字节 ÷ 核心 Proxy 总账字节”，不代表开关开启时长；核心总账读取失败只使该指标不可用。点击或用键盘触发榜单行会打开独立趋势窗口：点击应用时继承当前域名筛选，点击域名时继承当前应用筛选；窗口展示每日上下行堆叠柱、30 天合计、活跃日均、峰值日、有流量天数和固定日期明细。趋势只查询既有日聚合，不保存新的图表或连接明细。快速菜单中的最近 30 天 Proxy 柱图直接读取核心分类总账，不依赖历史归因开关。

应用名称归一化从升级后的新观测开始生效。既有日聚合没有保存进程路径，无法安全反推宿主 `.app`，因此旧名称不迁移，最多在 30 天保留窗口内与新名称并存。

“清空归因历史”只删除连接日聚合；Proxy 流量模块的“清空本地统计”同时删除核心流量账本、秒表式任务和连接归因历史。两者都不删除订阅余额数据、Controller 地址或 Secret。

Debug 日志会使用固定枚举记录连接尝试来源、取消来源、最近快照间隔、自动重连原因、错误代码、等待秒数和结果，不写入服务地址、访问密钥、节点或原始错误文本。看门狗主动取消不会再记成外部网络断开。

## MVP-1 边界

MVP-1 只提供当前实时速度，不提供：

- 今日或总累计
- 手动统计记录点
- 应用重启后的恢复
- 机场订阅余额走势
- 本机统计与机场计费的强一致对账

这些能力分别属于后续 MVP-2 和订阅余额阶段。
