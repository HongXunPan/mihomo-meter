# Windows 阶段 W2C 实机指南

## 1. 验收定位

本指南用于 Windows 10 22H2 x64 标准用户对 W2C 订阅配额做一次性验收。执行前应确认对应提交的“Windows 构建与测试”已成功，再下载名称以 `mihomo-meter-windows-w2c-x64-` 开头的 artifact。

自动化已经覆盖领域、账本、YAML、HMAC、HTTPS/代理约束、调度和生命周期隔离；本指南只验证真实 Windows 壳层、Credential Manager、文件夹选择器、Mihomo、机场响应和视觉交互。不要提交 Controller Secret、订阅 URL、Token、节点或完整 `profiles.yaml`。

## 2. 前置准备

1. 解压 artifact 到普通用户可写目录，不覆盖旧目录；双击 `MihomoMeter.Windows.App.exe`。
2. 使用与 W1/W2B 相同的本机 Clash Verge Rev/Mihomo 环境，确认 External Controller 可连接。
3. 准备一个真实 Clash Verge Profile 目录，其根部包含 `profiles.yaml`，最好包含两个以上远程 Profile；不把目录或文件复制进仓库。
4. 保持至少一个 HTTPS 订阅可返回 `Subscription-Userinfo`；若真实订阅不返回该响应头，应记录“机场未返回配额响应头”，不能填造成功结果。

本阶段新增文件位于 `%LOCALAPPDATA%\HongXunPan\MihomoMeter\`：

- `quota.sqlite3`：独立配额账本；
- `profile-directory.json`：用户选择的非敏感目录路径；
- 既有 `traffic.sqlite3` 与 Controller 设置不得被配额清空影响。

## 3. 基础与回归

1. 启动后确认主窗口侧栏包含“实时监控”“Proxy 流量”“订阅余额”，窗口右侧无异常空白。
2. 连接 Mihomo，确认 W1 实时速度、分类覆盖率和断线/重连仍工作，值刷新时不整页闪烁。
3. 在“Proxy 流量”确认 W2B 今日/历史累计、统计任务、30 日 X/Y 轴和通知区域任务菜单无回归。
4. 关闭主窗口，确认进程继续驻留通知区域；双击图标可恢复窗口；明确“退出”后进程和图标消失。

任一 W0–W2B 已通过能力回归，都应停止 W2C 验收并报告。

## 4. 当前运行订阅轻量模式

1. 连接成功后进入“订阅余额”，观察“当前运行订阅”状态。
2. 若 Mihomo 恰好暴露一个有效候选，应出现“确认并启用”；确认后生成“当前运行订阅”卡片和首个有效快照。
3. 未确认前不得自动建立轻量订阅；确认文案应明确机场配额不与本机 Proxy 流量对账。
4. 若当前配置是零候选或多候选，应明确显示不可启用/已暂停，不能猜选、合并或写零。
5. 断开 Controller 后确认观察停止且旧值带状态保留；重新连接后恢复检查。切换 Controller 地址或运行来源时，轻量追踪应暂停并要求重新确认。

零/一/多候选受真实配置影响，只记录本机实际覆盖的分支；不要为补齐截图修改或泄露订阅。

## 5. Profile 授权与身份

1. 点击“选择 Profile 目录”，确认使用 Windows 原生文件夹选择器；取消选择不应改变现状。
2. 选择根部含 `profiles.yaml` 的目录，确认只显示远程 Profile，当前 UID 有明确标识；HTTP Profile 可见但不能开启主动查询。
3. 为两个以上 HTTPS Profile 分别开启追踪，并选择不同的 1/3/6/12/24 小时间隔；重启应用后选择与间隔应恢复。
4. 在 Clash Verge 中只改一个 Profile 的名称或让其配置文件发生原子替换，确认约 1 秒内列表更新且既有历史不丢失。
5. 若实际安全地更换同一 UID 的 URL，确认历史仍归同一 UID，但下一次查询使用新地址；界面和数据库不得展示原始 URL。
6. 点击“停止目录访问”，确认观察停止、Profile 追踪暂停、历史保留；重新选择后可恢复管理。

若目录是符号链接、Junction 或其他重解析点，应明确拒绝；不要为了测试破坏 Clash Verge 正在使用的真实配置。

## 6. 主动查询与失败保护

1. 保持 Mihomo mixed/HTTP/SOCKS 至少一个本地代理端口可用，点击单个“立即查询”；成功后剩余、已用、总量、更新时间和查询计划更新。
2. 点击“立即查询全部”，确认多个 Profile 顺序完成，界面不并发轰炸机场且每个失败互不阻断。
3. 成功后 60 秒内再次点击单项查询，应处于冷却；超时或网络失败允许立即重试。
4. 临时关闭 Mihomo 本地代理端口但保留 Controller（仅在你熟悉配置且可回滚时），确认显示“本地代理不可用”，旧快照保留且没有直连成功迹象。
5. 遇到 HTTP 状态异常、缺少响应头、格式错误、超时或 HTTPS 重定向失败时，应显示安全摘要，不写零、不清空趋势、不显示 URL。

不得用抓取或回显真实订阅 URL 的方式证明代理路径；可用机场访问日志的请求时间或本机防火墙行为做辅助观察，但不是必填证据。

## 7. 卡片、趋势与周期

1. 多个订阅卡片应同屏稳定显示；更新某一卡片时，其他卡片和已完成状态不应整行闪烁或先变 `--`。
2. 依次切换 24 小时、7 天、30 天、12 月，确认每档都有 X/Y 轴刻度、真实时间定位和范围新增摘要。
3. 把指针移到真实点附近，右上角明细应切换到最近真实点的时间和累计；移出后恢复最新点。
4. 无样本范围显示明确空态，不伪造折线；发生周期变化或累计方向回退时线段应断开。
5. 预计耗尽在样本不足、跨度不足 6 小时、周期待确认、数据过期或无近期消耗时给出原因，不猜数字。
6. 若真实订阅在验收期间发生累计下降，新周期应显示“确认新周期”；确认后才允许该周期参与预测。没有自然发生时，将该项记录为“条件未触发”，不人工篡改数据库。

## 8. 通知区域、清空与重启

1. 右键通知区域图标，确认“订阅余额”子菜单展示打开菜单前的稳定文字快照，最多五个订阅，超出部分有数量提示。
2. 子菜单可进入完整“订阅余额”页；可用时点击“立即查询全部”，菜单关闭后才开始查询，菜单跟踪期间不冻结或改变高度。
3. 在配额页执行“清空配额数据”，确认二次提示准确；清空后卡片、追踪选择、快照、周期、事件和调度状态消失。
4. 清空后确认 Controller 仍能自动连接、Profile 目录路径仍存在、W2B `traffic.sqlite3` 的今日/历史累计和统计任务未变化。
5. 重新启用一个 Profile、完成一次查询并退出应用；再次启动后确认快照、查询计划和目录恢复。

### 通过标准与反馈

通过需要同时满足：对应 CI 全绿；W2C 基础、至少一种身份模式、主动查询、四档趋势、通知区域、清空和重启恢复通过；W0–W2B 无回归；没有管理员权限、直连、敏感字段落盘或配额故障阻断实时监控。

反馈只需提供：失败步骤、预期/实际、应用界面截图、Action run 链接、是否可稳定复现。若需附日志或数据库结构，先确认不含 Secret、URL、Token、节点和本机敏感路径；不要上传真实数据库或 `profiles.yaml`。
