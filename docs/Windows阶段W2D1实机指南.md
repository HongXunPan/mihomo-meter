# Windows 阶段 W2D-1 实机指南

## 1. 验收定位

本指南用于 Windows 10 22H2 x64 标准用户验证实时连接与通知区域 Top 5。执行前确认对应提交的“Windows 构建与测试”成功，再下载并解压名称以 `mihomo-meter-windows-w2d-x64-` 开头的 artifact。

不要上传 Controller Secret、订阅 URL、连接 ID、完整进程路径、目标 IP、节点、规则、真实响应、数据库或本机路径。反馈可使用虚构名称描述现象。

## 2. 自动化与基础回归

1. 确认静态检查、Core 单元测试、App Release 构建和自包含发布全部成功。
2. 以标准用户启动应用并连接真实 Mihomo Controller，不以管理员身份运行 Meter 或 Mihomo 客户端。
3. 确认 Proxy、DIRECT、REJECT、未知速率与分类覆盖率仍正常刷新。
4. 快速检查统计任务、30 日图表、订阅余额、关闭隐藏、悬浮图标和明确退出没有回归。

任一 W0-W2C 能力回归，应停止验收并反馈。

## 3. 实时连接页面

1. 进入“Proxy 流量”，确认顶部可在“流量统计”和“实时连接”之间切换；往返切换后统计任务与筛选状态仍保留。
2. 在“实时连接”选择 Proxy，制造持续下载和上传，确认连接行出现脱敏域名、应用、上下行速率、累计与时长。
3. 切换“连接 / 应用 / 域名”，确认连接模式逐条显示；应用与域名模式分别聚合相关项数、连接数、双向速率和累计。
4. 输入应用或域名的部分文字，确认搜索不区分大小写；清空搜索后恢复全部当前连接。
5. 切换“直连”，制造 DIRECT 流量，确认只显示直连连接，不混入 Proxy；再切回 Proxy，确认两类列表相互独立。
6. 没有主机名或应用时只能显示“未知域名”或“未知应用”，不得用目标 IP、节点或规则猜测补位。

若速率每帧闪回 `--`、整行反复闪烁、列表顺序无真实速率变化却持续跳动，记录失败。

## 4. 识别诊断与生命周期

1. 在 Proxy 实时页检查进程识别提示：`always`、`strict`、`off` 或“不可确认”必须与 Mihomo 当前只读配置一致，并显示本次会话应用识别数。
2. `off` 应显示警告；未知值或 `/configs` 暂不可用不得阻止实时监控，也不得修改 Mihomo 配置。
3. 主动断开，确认活动连接、速率和覆盖率样本清空；重新连接后只出现新会话连接。
4. 若测试中自然发生 stale、重连或内核计数器重置，确认旧列表立即清空。不要为了触发异常修改数据库或破坏客户端配置。
5. 退出并重启，确认上次连接明细、搜索文本和实时列表不会恢复。

## 5. 通知区域 Top 5

1. 保持多条 Proxy 与 DIRECT 连接有真实传输，右键通知区域图标。
2. 确认存在“活动 Proxy Top 5”和“活动直连 Top 5”两个原生子菜单，父项显示当前活跃数。
3. 每个子菜单始终恰好五个槽位；不足五条时空位显示“暂无传输”，超过五条时只保留总速率最高的五条。
4. 非空槽位显示脱敏域名、应用、双向速率与累计，不出现连接 ID、完整路径、目标 IP、节点、规则或链路。
5. 点击“查看实时连接…”，确认菜单先关闭，再复用现有主窗口并定位到对应 Proxy 或直连页面。
6. 重复打开菜单，确认不会额外建立连接、请求 Controller 或阻塞 UI。

## 6. 通过标准与反馈

通过需要同时满足：对应 CI 全绿；Proxy/DIRECT 分类正确；三种查看方式、搜索、速率、累计和时长正常；页面与行不持续闪烁；断开/stale/重连/reset 清理旧状态；诊断只读且失败隔离；两个原生 Top 5 子菜单固定五槽；隐私字段未显示或落盘；W0-W2C 无回归。

反馈只需提供 Action run 链接、失败步骤、预期/实际、Mihomo `find-process-mode` 的枚举值，以及是否验证了 Proxy/DIRECT 和超过五条活跃连接。不要附带真实连接内容。
