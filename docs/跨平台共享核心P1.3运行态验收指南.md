# 跨平台共享核心 P1.3 运行态验收指南

## 1. 文档定位

- 状态：已通过（2026-08-12）
- 适用范围：P1.3 字节数、完整速率和紧凑速率受保护主路径
- macOS 验收基线：`dd891d35dc9f8cfff1567b9c5e982d020cf9683c`
- Windows 复验基线：`7281af91ca6279802410a8d9cee11be3a4322c6f`

本指南只验证共享核心已在三类流量格式中成为受保护主路径，并且异常时仍具备原生回退能力。它不扩大到 View、窗口生命周期、网络、持久化、凭据或其他算法候选，也不以 CI 代替真实设备证据。双端结果见[验收记录](跨平台共享核心P1.3验收记录-2026-08-12.md)。

## 2. 前置条件与证据边界

1. macOS 与 Windows 分别执行至少两次独立启动，其中一次为应用完全退出后的冷启动。
2. 每个平台至少保持一次连续连接 30 分钟，并覆盖“空闲 → 产生流量 → 再次空闲”。
3. Windows 必须使用 Windows 10 22H2 x64 标准用户和本指南指定的 CI 产物；macOS 使用真实设备及项目现有签名、沙盒和前台进程启动方式。
4. 只反馈平台、系统版本、构建 commit、起止时间、场景结论和粗粒度诊断结果。不得复制完整日志，不得提交 Controller Secret、订阅地址、节点、路径、连接目标或真实响应。

## 3. 三类格式场景

| 格式 | macOS 触发场景 | Windows 触发场景 | 必须出现的路由结果 |
| --- | --- | --- | --- |
| `byte_count` | 打开流量统计或连接分析，确认累计流量出现 | 打开 Proxy 流量或连接分析，确认累计流量出现 | `result=shared_primary status=matched` |
| `rate` | 连接 Mihomo 后查看分类速率或运行详情 | 打开主窗口分类速率或实时连接 | `result=shared_primary status=matched` |
| `compact_rate` | 查看状态菜单连接列表中的紧凑速率 | 查看通知区提示或悬浮窗速率 | `result=shared_primary status=matched` |

三类界面都应继续使用十进制 1000 进位和既有 macOS 精度口径，文本、单位、布局和刷新行为不得发生可见变化。

## 4. macOS 验收

1. 先从菜单明确退出正在运行的 Mihomo Meter，再在源码仓根目录运行：

```bash
scripts/build-debug.sh --run
```

2. 连接 Mihomo，依次覆盖三类格式场景；其中一次启动连续连接至少 30 分钟并覆盖“空闲 → 产生流量 → 再次空闲”。
3. 明确退出应用，确认前台命令返回；再次运行同一命令并复验三类场景。
4. 通过帮助菜单打开诊断日志目录，或只筛选以下文件中的共享核心事件：

```text
~/Library/Containers/com.HongXunPan.MihomoMeter/Data/Library/Logs/MihomoMeter/diagnostics.log
```

每个进程至少应出现：

```text
event=shared_core.runtime_probe result=ready
event=shared_core.traffic_route format=byte_count result=shared_primary status=matched
event=shared_core.traffic_route format=rate result=shared_primary status=matched
event=shared_core.traffic_route format=compact_rate result=shared_primary status=matched
```

## 5. Windows 验收

Windows 基线来自 [Windows 构建与测试 run 31554732014](https://github.com/HongXunPan/mihomo-meter/actions/runs/31554732014)：

```text
mihomo-meter-windows-w3-preview-0.0.0-7281af91ca6279802410a8d9cee11be3a4322c6f
```

1. 下载并解压 CI artifact，再解压其中的 `Mihomo-Meter-0.0.0-windows-x64-portable.zip`。
2. 使用 Windows 10 22H2 x64 标准用户进入解压后的 `Mihomo Meter` 目录，不以管理员身份运行。
3. 从 PowerShell 显式打开限量启动控制台：

```powershell
$env:MIHOMO_METER_STARTUP_CONSOLE = "1"
.\MihomoMeter.Windows.App.exe
```

4. 连接 Mihomo，依次覆盖三类格式场景；其中一次启动连续连接至少 30 分钟并覆盖“空闲 → 产生流量 → 再次空闲”。
5. 从通知区域明确退出应用，再用同一命令启动并复验三类场景。

每个进程至少应出现：

```text
WINDOWS_STAGE stage=shared_core_runtime_ready
WINDOWS_DIAGNOSTIC event=shared_core.traffic_route format=byte_count result=shared_primary status=matched
WINDOWS_DIAGNOSTIC event=shared_core.traffic_route format=rate result=shared_primary status=matched
WINDOWS_DIAGNOSTIC event=shared_core.traffic_route format=compact_rate result=shared_primary status=matched
```

## 6. 放行与停止条件

每个进程中，同一 `format + result + status` 组合只能出现一次。以下条件必须全部满足：

- 双端各完成两次独立启动，且至少一次连续连接 30 分钟；
- 双端三类格式都出现 `shared_primary + matched`；
- 不出现 `native_fallback`、`shared_core.traffic_shadow`、`WINDOWS_FAILURE` 或启动异常；
- 不出现重复诊断失控、敏感内容、展示变化、连接异常或明显性能退化。

任一条件失败时立即停止收口，不创建通过记录、不合并 P1.3-5，并按格式回退或定位环境问题。缺少任一正向事件属于证据不完整，不能按“未发现异常”放行。
