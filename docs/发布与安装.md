# 发布与安装

## 分发边界

Mihomo Meter 通过 GitHub Releases 分发 DMG，不上架 Mac App Store，也不使用 Apple Developer Program、Developer ID 或 Apple 公证。

正式应用固定使用：

- Bundle ID：`com.HongXunPan.MihomoMeter`
- 自签名证书名称：`Mihomo Meter By HongXunPan`
- Sparkle 版本：`2.9.4`
- 版本号：无前导零的 `X.Y.Z`
- Git 标签：`vX.Y.Z`

自签名证书不建立 Apple 信任链。首次安装时，macOS Gatekeeper 会提示无法验证开发者；用户需要在 Finder 中按住 Control 点击应用并选择“打开”，或在“系统设置 → 隐私与安全性”中确认仍要打开。不要建议用户全局关闭 Gatekeeper。

Sparkle 会作为 Framework 嵌入开发版和正式版。Xcode 开发构建继续使用
`MihomoMeter.entitlements`，保留 Hardened Runtime 的 Library Validation；
固定自签名证书没有 Apple Team ID，无法依靠同一 Team ID 通过该校验，因此最终
自签名产物改用 `MihomoMeterSelfSignedRelease.entitlements`，只为正式版声明
`com.apple.security.cs.disable-library-validation`。这项例外不会关闭应用沙盒、
Hardened Runtime、代码签名、固定指定要求或 Sparkle Ed25519 更新验签。

## 为什么证书必须保持不变

发布脚本把固定 Bundle ID 和自签名证书 SHA-1 写入应用的代码指定要求。Controller Secret 保存在登录钥匙串，钥匙串访问控制列表依据该指定要求识别后续版本。

因此：

- 同一证书签署的新版本可以无痛读取已有 Secret。
- 从旧 Data Protection Keychain 版本首次升级时，需要重新填写一次 Secret。
- 丢失、重建或替换证书会改变应用身份，必须作为凭据迁移破坏性变更处理。
- 证书私钥及导出的 P12 不得提交到仓库、Release 或构建日志。

Sparkle 的 Ed25519 更新签名与 macOS 代码签名是两条独立校验链：固定自签名证书维持应用身份和 Keychain ACL，Ed25519 私钥负责证明更新包由项目发布。Ed25519 公钥会公开嵌入应用，私钥不得进入仓库、Release 或日志。项目没有 Developer ID 作为换钥兜底，因此必须离线备份 Ed25519 私钥；丢失后，已经安装的版本将无法无痛切换到新公钥。

## 首次准备发布证书

证书只需生成一次并长期安全保存。可在“钥匙串访问”中创建代码签名自签名证书：

1. 名称填写 `Mihomo Meter By HongXunPan`，不要包含邮箱或其他隐私联系方式。
2. 身份类型选择“自签名根证书”，证书类型选择“代码签名”。
3. 将证书与对应私钥一并导出为带强密码的 P12。
4. 离线保存 P12 与密码的受控备份；证书丢失后无法为已有钥匙串 ACL 生成等价身份。

在 GitHub 仓库的 Actions Secrets 中配置：

- `MIHOMO_METER_SIGNING_P12_BASE64`：P12 文件的 Base64 内容。
- `MIHOMO_METER_SIGNING_P12_PASSWORD`：P12 导出密码。
- `SPARKLE_ED_PRIVATE_KEY_BASE64`：Sparkle `generate_keys -x` 导出的私钥文件再进行 Base64 编码后的内容。

GitHub Actions 使用仓库自动提供的 `GITHUB_TOKEN` 创建标签和 Release，不需要个人 GitHub Token、Apple ID 密码、Apple API Key 或 Apple Developer Program 凭据。

## 应用内更新边界

- `0.1.x` 没有内置 Sparkle，首次升级到 `0.2.x` 仍需手动下载并安装 DMG。
- 安装包含 Sparkle 的版本后，应用启动时会读取 GitHub 最新 Release 的 `appcast.xml`，也可以手动点击“检查更新”。
- 更新提示、发布说明、下载进度和安装确认由 Sparkle 标准界面处理。
- 应用关闭自动下载和后台静默安装；只有用户确认后才下载 Universal DMG。
- Universal DMG 会在解压前校验 Ed25519 签名，安装后的应用仍必须通过固定自签名身份校验。
- 由于应用未公证，首次手动安装仍需处理 Gatekeeper 提示；Sparkle 更新链路也不能替代 Apple 公证，正式放行前需使用两个连续版本做真实安装验证。

## 自动发布

在 GitHub Actions 中手动运行“发布自签名 DMG”工作流并填写 `X.Y.Z`。工作流只接受 `main` 分支，并按以下顺序执行：

1. 校验版本号，拒绝已存在的标签或 Release。
2. 执行严格 Swift 格式检查、应用构建和全部测试。
3. 在临时用户钥匙串中导入并信任固定自签名证书。
4. 分别构建 `arm64`、`x86_64` 和同时包含两者的 `universal` Release 应用。
5. 写入版本号和构建号，签名 Sparkle 组件，并使用正式自签名专用权限签名主应用，校验权限与指定要求。
6. 分别生成并签名三个带架构后缀的 DMG，挂载复核内容，并在宿主机支持的架构上执行三秒真实启动冒烟。
7. 汇总三个 DMG 的 `SHA256SUMS`。
8. 根据上一个版本标签到当前提交之间的记录，按功能、修复、文档和内部改进生成中文摘要。
9. 从 GitHub Secret 解码临时 Ed25519 私钥，使用 Sparkle 官方 `generate_appcast` 为 Universal DMG 生成签名 `appcast.xml`，随后清理私钥、临时钥匙串和证书文件。
10. 最后创建 `vX.Y.Z` 标签和 GitHub Release，保留 GitHub 自动生成内容，并上传三个 DMG、`appcast.xml` 与校验文件。

标签只在构建、测试和打包全部成功后创建，避免失败构建留下不可用版本。
中文摘要由仓库内脚本确定性生成，不调用外部 AI 服务，也不需要额外开发者密钥。
同一分类下，去除规范前缀后标题完全一致的提交会合并为一条并保留多个短 commit hash；
`fixup!` 和 `squash!` 提交不会单独展示。语义相近但标题不同的提交不会自动合并，避免误合并。

“更新 DMG 下载量徽章”工作流会在发布工作流成功结束后、每日定时任务以及维护者手动触发时，
通过 GitHub Releases API 汇总所有正式版本中三个 DMG 资产的 `download_count`，并把
Shields Endpoint 所需 JSON 发布到自动维护的 `badges` 分支。统计不包含草稿、预发布版本、
`appcast.xml` 或 `SHA256SUMS`，也不能用于判断唯一用户数或实际安装量。

Release 提供以下下载选择：

- Apple Silicon Mac：`Mihomo-Meter-X.Y.Z-macos-arm64.dmg`
- Intel Mac：`Mihomo-Meter-X.Y.Z-macos-x86_64.dmg`
- 不确定本机架构或需要同时兼容两类 Mac：`Mihomo-Meter-X.Y.Z-macos-universal.dmg`

应用内更新固定下载 Universal DMG。`appcast.xml` 通过
`https://github.com/HongXunPan/mihomo-meter/releases/latest/download/appcast.xml`
提供稳定入口，其中的下载地址固定指向对应版本 Release 里的 Universal DMG。

## 本机构建 DMG

当前用户钥匙串已导入并信任固定证书及私钥时，可以运行：

```bash
scripts/build-release-dmg.sh \
  --version 0.1.0 \
  --build-number 1 \
  --architecture universal \
  --output-dir dist
```

`--architecture` 支持 `arm64`、`x86_64` 和 `universal`，未指定时默认构建
`universal`。脚本固定使用 `Mihomo Meter By HongXunPan`，以上示例产物为：

```text
dist/
├── Mihomo-Meter-0.1.0-macos-universal.dmg
└── SHA256SUMS
```

`dist/` 和 `.build/` 已被 Git 忽略。发布前仍应在一台没有开发证书和源码环境的 macOS 上验证首次安装、Gatekeeper 提示、重新填写 Secret，以及使用同一证书签名的下一版本能否直接读取 Secret。

构建脚本会以 `MIHOMO_METER_TEST_MODE=1` 直接启动挂载后的应用三秒，用于发现
dyld、代码签名或 Framework 加载阶段的启动失败。测试模式不会装配生产监控、
访问真实 Keychain 或写入应用诊断日志；当前宿主不支持目标单架构时会明确跳过，
Universal DMG 则会使用宿主原生架构执行。

本地构建 DMG 不需要 Sparkle 私钥。只有准备正式 appcast 时，才使用受控私钥文件和 Sparkle 依赖自带的 `generate_appcast`：

```bash
scripts/generate-sparkle-appcast.sh \
  --version 0.2.0 \
  --dmg dist/Mihomo-Meter-0.2.0-macos-universal.dmg \
  --release-notes dist/RELEASE_NOTES.md \
  --private-key ~/.config/mihomo-meter/sparkle_ed25519_private_key \
  --generate-appcast /路径/Sparkle/bin/generate_appcast \
  --output dist/appcast.xml
```

该命令不会复制私钥到 `dist/`；脚本临时目录位于被忽略的 `.build/`，执行结束后自动清理。
