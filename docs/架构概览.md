# 架构概览

## 目标

Mihomo Meter 采用原生 macOS 技术栈，在状态栏展示经过 Mihomo Proxy 出口的实时网速和累计流量。

## 技术栈

- Swift 6
- AppKit `NSStatusItem`
- SwiftUI
- `URLSession`
- `URLSessionWebSocketTask`
- macOS Data Protection Keychain

SQLite 将在 MVP-2 统计账本阶段引入，MVP-1 不持久化流量累计。

## 分层

```text
状态栏与详情界面
        ↓
TrafficMonitor 界面门面与状态归约
        ↓
监控协调、单次运行与单流会话
        ↓
实时测量领域服务
        ↓
Mihomo Controller、Keychain 与诊断日志
```

### Application

负责应用生命周期和模块装配，不承载连接分类或累计算法。XCTest 宿主启动应用可执行文件时跳过生产模块装配，不访问真实 Keychain 或应用诊断日志。

### Domain

保存与界面和网络实现无关的流量模型、分类规则和统计口径。

### Infrastructure

负责 Mihomo Controller、WebSocket、Data Protection Keychain 和 Debug 诊断日志等系统能力。Keychain 查询固定使用应用自身 App ID 的默认访问组，不开启跨应用共享，也不自动迁移传统文件型 Keychain 条目。诊断事件、连接错误映射和文件写入相互分离；日志只接收类型化事件，不接收 Secret、服务地址、原始错误文本或真实响应。

### Presentation

负责状态栏、弹层和用户可见状态，不直接解析 Mihomo 响应。

### 当前模块

MVP-1 已按职责实现：

- `TrafficMonitor`
- `TrafficMonitorState`
- `TrafficMonitorReducer`
- `ControllerConfigurationStore`
- `TrafficMonitoringCoordinator`
- `TrafficMonitoringRun`
- `MihomoMonitoringSession`
- `MihomoControllerClient`
- `ConnectionStreamCollector`
- `ConnectionLivenessWatchdog`
- `ProxyCatalog`
- `ConnectionDeltaTracker`
- `ProxyClassifier`
- `TrafficRateAggregator`
- `TrafficMeasurementSession`
- `DebugDiagnosticLogger`
- `AppDiagnosticEvent`
- `ConnectionDiagnosticReason`

`TrafficMonitor` 只保留 SwiftUI 可观察门面、用户操作入口和类型化 Publisher；`TrafficMonitorReducer` 将协调事件归约为 `TrafficMonitorState`。`ControllerConfigurationStore` 隔离地址与 Keychain 的启动、验证后保存语义。`TrafficMonitoringCoordinator` 管理运行切换、取消来源和过期运行隔离，`TrafficMonitoringRun` 管理地址验证、鉴权、自动重连与退避，`MihomoMonitoringSession` 管理一条 WebSocket 实时流、目录刷新和存活检测。

`ConnectionLivenessWatchdog` 独立管理数据超时提示、强制重连阈值、流代次和稳定连接判断。`TrafficMeasurementSession` 组合代理分类、连接增量和速率窗口，统一维护单条实时流的测量基线，并返回活动 Proxy 叶子、目录刷新信号和速率结果。`TrafficLedger` 将在 MVP-2 进入长期统计时引入。

## 职责增长边界

为避免 `TrafficMonitor` 再次膨胀，后续改动按以下边界落位：

1. 新增界面状态或文案转换时，扩展 `TrafficMonitorState` 与 `TrafficMonitorReducer`。
2. 新增连接触发方式、运行替换或取消诊断时，扩展 `TrafficMonitoringCoordinator`。
3. 新增鉴权、重试条件、退避或终止错误映射时，扩展 `TrafficMonitoringRun`。
4. 新增单流存活判断、快照接收或代理目录刷新时，扩展 `MihomoMonitoringSession`。
5. 新增分类、连接增量或速率计算时，扩展 `TrafficMeasurementSession` 及对应领域类型。
6. 新增配置与凭据持久化语义时，扩展 `ControllerConfigurationStore`，不得从界面层直接访问 Keychain。
7. 测试按配置、生命周期、状态归约和单流会话分别维护；共享替身放在测试支持文件，不再集中回单一测试类。

## 稳定边界

1. Mihomo 集成只使用公开 Controller API。
2. Proxy、DIRECT、REJECT 和未知流量独立建模。
3. 连接级数据只用于内存计算，默认不持久化目标明细。
4. 断线时实时速率必须归零，不沿用旧值。
5. 本机累计不等同于机场计费流量。
6. Debug 诊断日志只记录固定脱敏事件，不得接收或推导 Controller Secret。
