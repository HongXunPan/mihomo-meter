# 架构概览

## 目标

Mihomo Meter 采用原生 macOS 技术栈，通过随窗口显示的 Dock 与状态栏原生菜单展示 Mihomo Proxy 出口的实时网速、累计流量、订阅余额和连接分析。

## 技术栈

- Swift 6
- AppKit `NSStatusItem`、`NSMenu` 与 `NSWindowController`
- SwiftUI
- `URLSession`
- `URLSessionWebSocketTask`
- 系统 `SQLite3`
- macOS 登录钥匙串
- Yams 6.2.2
- Sparkle 2.9.4

共享核心 P1.4 双端门禁已通过；流量格式现共享优先、原生懒回退，[P1.3 受保护路径](跨平台共享核心P1.3受保护主路径技术方案.md)保留为回滚入口。代理分类 P2 双端门禁也已通过；详见[P2 方案](跨平台共享核心P2代理分类技术方案.md)与[最终验收](跨平台共享核心P2-7验收记录-2026-08-12.md)。

## 分层

```text
状态栏快速菜单与应用窗口
        ↓
TrafficMonitor 界面门面与状态归约
        ↓
监控协调、单次运行与单流会话
        ↓
实时测量领域服务
   ↓             ↘
统一连接增量       Mihomo Controller
   ↙       ↘       Keychain 与诊断日志
流量账本     可选连接归因账本
```

阶段 2 的当前运行订阅轻量模式、Clash Profile 身份控制面、主动查询调度、额度账本和展示边界见[订阅配额架构](订阅配额架构.md)。

阶段 3 的连接实时测量、可选日归因和隐私边界由产品方案维护。基础设施只把非 IP 主机名和归一化应用名称映射到领域模型：应用名优先取进程路径最外层 `.app`，再降级到进程值或文件名，完整路径立即丢弃；领域层在同一次连接增量计算中输出分类总量与逐连接增量，Proxy 与 DIRECT 使用独立实时聚合状态。两类实时连接只在内存中存在，历史日聚合仍仅由用户明确开启后写入独立 Proxy 归因账本。应用或域名趋势由账本按精确条件查询既有日聚合并补齐 30 天零值，不新增索引、迁移或图表持久化。

### Application

负责应用生命周期、模块装配和界面展示协调，不承载连接分类或累计算法。`AppPresentationCoordinator` 统一编排状态栏原生快速菜单、单一统计主窗口和 Controller 设置窗口；`StatusMenuController` 将自然高度 SwiftUI 摘要、带实时 Badge 的标准父菜单项、区段内原生子菜单和模块跳转项装配为同一 `NSMenu` 菜单项流，由 AppKit 在超过屏幕可用高度时统一滚动。统计窗口控制器长期持有并复用连接归因趋势窗口控制器，关闭趋势窗口时清除查询目标和结果。应用以 accessory 策略静默启动；普通窗口存在时使用 regular，全部关闭后切回 accessory。XCTest 宿主启动应用可执行文件时跳过生产模块装配，不访问真实 Keychain 或应用诊断日志。

### Domain

保存与界面和网络实现无关的流量模型、分类规则和统计口径。

### Infrastructure

负责 Mihomo Controller、WebSocket、Profile YAML、SQLite 账本、登录钥匙串、Sparkle 更新和本地诊断等系统能力。通用 `SQLiteConnection` 位于 Storage 层；本机 Proxy 流量使用 `traffic.sqlite3`，订阅额度使用 `quota.sqlite3`，可选连接归因使用 `connection-analytics.sqlite3`，三类统计不共享表或累计口径。Keychain 查询使用传统文件型钥匙串且不声明访问组。`SparkleAppUpdater` 只包装 Sparkle 标准更新控制器，读取签名 appcast。日志与用户导出的隔离边界见[诊断与导出](诊断与导出.md)。

### Presentation

负责状态栏原生快速菜单、Controller 设置窗口、统计主窗口、归因趋势窗口和用户可见状态，不直接解析 Mihomo 响应、Profile YAML 或 SQLite。Proxy 页面容器只协调“流量统计 / 实时连接”分段；实时页再切换 Proxy/直连，搜索与连接、应用、域名聚合由纯展示模型完成。任务内容由独立视图承载，连接分析页只承载 Proxy 历史归因、记录覆盖率和趋势展示回调。

`TrafficMonitor` 只保留 SwiftUI 可观察门面、用户操作入口和类型化 Publisher；`TrafficMonitorReducer` 将协调事件归约为 `TrafficMonitorState`。`ControllerConfigurationStore` 隔离地址与 Keychain 的启动、验证后保存语义。`TrafficMonitoringCoordinator` 管理运行切换、取消来源和过期运行隔离，`TrafficMonitoringRun` 管理地址验证、鉴权、运行配置摘要、自动重连与退避，`MihomoMonitoringSession` 管理一条 WebSocket 实时流、目录刷新和存活检测。

`ConnectionLivenessWatchdog` 独立管理数据超时提示、强制重连阈值、流代次和稳定连接判断。`TrafficMeasurementSession` 组合代理分类、连接增量和速率窗口，统一维护单条实时流的测量基线，并额外输出不经过平滑的原始账本观测。`TrafficStatisticsController` 消费原始观测并维护界面可用性；`SQLiteTrafficLedger` actor 保证增量、累计基线和区间状态原子更新。统计任务仅保存开始和结束时的 Proxy 基线，多个任务共享同一账本。

统计展示分为两层：状态栏原生快速菜单中的 `TrafficStatisticsSummaryView` 只展示固定高度的累计摘要和近 30 天图表；“统计任务”父项使用原生纯计数 Badge，完整状态由无障碍描述和子菜单页头表达。`StatusMenuTrafficTasksMenuCoordinator` 长期持有固定子菜单根视图，五个索引稳定的槽位按进行中优先、今日结束补足的口径更新，并展示 Proxy 下载、上传、合计和时间信息，快捷开始和停止不结束菜单跟踪；
`TrafficStatisticsWindowController` 使用普通可缩放主窗口承载自定义名称新建、筛选、行内编辑和危险操作确认；点击子菜单任务主体会关闭菜单并将该窗口定位到“Proxy 流量 / 流量统计”。
`StatusMenuFactory` 负责创建自然高度 SwiftUI 摘要、活动连接与状态子菜单、统计任务和订阅走势固定详情；`StatusMenuController` 将公共父项和区段内父项与模块跳转项装配为同一 `NSMenu` 菜单项流，并按 Controller 配置状态控制显隐和内容尺寸。统计任务子菜单直接观察同一个统计 Controller，开始和停止只替换既有槽位内容；订阅摘要只展示固定进度行，“查看订阅走势”和“查看订阅余额统计”依次紧随摘要。订阅走势的 AppKit tracking view 只采集归一化鼠标位置，长期持有的子菜单状态按 Profile、范围和菜单会话代次过滤旧事件，Swift Charts 只替换固定选中点与明细。连接设置、检查更新和退出继续使用标准 `NSMenuItem`。菜单外壳、材质、定位、互斥、外部点击关闭和屏幕溢出滚动均由 AppKit `NSMenu` 管理；自定义内容不建立嵌套滚动，也不手写 `Tab` 焦点循环。`ControllerSettingsWindowController` 使用普通窗口承载服务地址和 Secret 等键盘输入。
`AppPresentationCoordinator` 同步结束菜单跟踪，再激活并前置目标窗口、切换统计模块；各界面共享同一个
`TrafficStatisticsController`，不会复制账本或建立第二套统计状态。

## 职责增长边界

为避免 `TrafficMonitor` 再次膨胀，后续改动按以下边界落位：

1. 新增界面状态或文案转换时，扩展 `TrafficMonitorState` 与 `TrafficMonitorReducer`。
2. 新增连接触发方式、运行替换或取消诊断时，扩展 `TrafficMonitoringCoordinator`。
3. 新增鉴权、重试条件、退避或终止错误映射时，扩展 `TrafficMonitoringRun`。
4. 新增单流存活判断、快照接收或代理目录刷新时，扩展 `MihomoMonitoringSession`。
5. 新增分类、连接增量或速率计算时，扩展 `TrafficMeasurementSession` 及对应领域类型。
6. 新增配置与凭据持久化语义时，扩展 `ControllerConfigurationStore`，不得从界面层直接访问 Keychain。
7. 测试按配置、生命周期、状态归约和单流会话分别维护；共享替身放在测试支持文件，不再集中回单一测试类。
8. 新增更新策略或发布源时，扩展 `AppUpdateModel` 与 `SparkleAppUpdater`，不从界面直接请求网络或绕过 Sparkle 验签。
9. 新增累计、保留或区间任务语义时，扩展 `SQLiteTrafficLedger` 及独立持久化职责，不从速率窗口反推累计。
10. 阶段 2 的订阅额度、Profile 文件和目录授权改动遵循[订阅配额架构](订阅配额架构.md)中的职责边界。
11. 阶段 3 的连接元数据必须先经过基础设施最小化适配；`TrafficMeasurementSession` 只编排 Proxy 覆盖率、统一连接增量和 Proxy/DIRECT 独立实时速率，日聚合由 `ConnectionAnalyticsController` 与独立 Proxy 账本负责。核心 Proxy 日总量只通过同一 `SQLiteTrafficLedger` actor 的窄查询参与记录覆盖率，不得跨库查询，也不得把持久化职责堆入 `TrafficMonitor`。

## 稳定边界

1. Mihomo 集成只使用公开 Controller API。
2. Proxy、DIRECT、REJECT 和未知流量独立建模。
3. 连接 ID、开始时间、累计和实时速率只用于内存计算；用户明确开启后仅持久化本地日期、应用名称、完整主机名和 Proxy 上下行日聚合，不持久化连接明细。
4. 运行配置摘要和活动规则类型只用于当前快速菜单展示，不持久化规则匹配内容。
5. 断线时实时速率必须归零，不沿用旧值。
6. 本机累计不等同于机场计费流量。
7. 日志与用户导出均不得接收或推导 Secret、订阅 URL、Profile 名称或真实 UID，也不得自动上传。
8. 正式版本固定 Bundle ID 与自签名证书指定要求；证书轮换必须先设计凭据迁移。
9. Sparkle 辅助组件使用各自 Bundle ID 和默认指定要求，不得继承主应用指定要求或获得 Controller Secret 的 Keychain ACL 权限。
10. Xcode 开发构建保留 Library Validation；只有固定自签名正式产物使用专用权限关闭 Library Validation，并必须对挂载后的 DMG 执行无生产副作用的真实启动冒烟。
11. Controller Secret 只进入登录钥匙串，不得进入 SQLite 主库、WAL、SHM 或统计模型。
12. 订阅额度账本、Profile 目录和订阅地址遵循[订阅配额架构](订阅配额架构.md)的本地最小化边界。
13. 阶段 3.0 门禁已通过；真实主机和应用只用于内存实时列表，日聚合必须使用独立 `connection-analytics.sqlite3` 并由用户明确开启。
