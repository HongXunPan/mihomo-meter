# 架构概览

## 目标

Mihomo Meter 采用原生 macOS 技术栈，在状态栏展示经过 Mihomo Proxy 出口的实时网速和累计流量。

## 技术栈

- Swift 6
- AppKit `NSStatusItem`
- SwiftUI
- `URLSession`
- `URLSessionWebSocketTask`
- 系统 `SQLite3`
- macOS 登录钥匙串
- Sparkle 2.9.4

## 分层

```text
状态栏与详情界面
        ↓
TrafficMonitor 界面门面与状态归约
        ↓
监控协调、单次运行与单流会话
        ↓
实时测量领域服务
   ↙                ↘
SQLite 流量账本      Mihomo Controller
                     Keychain 与诊断日志
```

阶段 2.2 已把订阅额度基座装配为当前运行订阅轻量纵切：

```text
Mihomo /providers/proxies
            ↓
RuntimeQuotaObservationCoordinator
            ↓
RuntimeQuotaTrackingController
       ↙                         ↘
SQLiteQuotaLedger             弹层卡片与统一统计窗口
      ↓
quota.sqlite3 → 额度周期识别与趋势计算
```

### Application

负责应用生命周期和模块装配，不承载连接分类或累计算法。XCTest 宿主启动应用可执行文件时跳过生产模块装配，不访问真实 Keychain 或应用诊断日志。

### Domain

保存与界面和网络实现无关的流量模型、分类规则和统计口径。

### Infrastructure

负责 Mihomo Controller、WebSocket、SQLite 账本、登录钥匙串、Sparkle 更新和 Debug 诊断日志等系统能力。通用 `SQLiteConnection` 位于 Storage 层；本机 Proxy 流量使用 `traffic.sqlite3`，订阅额度使用独立的 `quota.sqlite3`，两类统计不共享表或累计口径。流量 SQLite actor 串行处理分类增量、内核会话、每日汇总和统计任务基线；额度 SQLite actor 串行处理订阅身份、原始额度观测、额度周期和趋势查询。Keychain 查询明确使用传统文件型钥匙串，不声明访问组，Secret 不进入 SQLite。`SparkleAppUpdater` 只包装 Sparkle 标准更新控制器，读取 GitHub Release 中的签名 appcast，并保持更新辅助组件与主应用代码指定要求相互隔离。诊断事件、连接错误映射和文件写入相互分离；日志只接收类型化事件，不接收 Secret、服务地址、原始错误文本或真实响应。

### Presentation

负责状态栏、弹层和用户可见状态，不直接解析 Mihomo 响应。

`TrafficMonitor` 只保留 SwiftUI 可观察门面、用户操作入口和类型化 Publisher；`TrafficMonitorReducer` 将协调事件归约为 `TrafficMonitorState`。`ControllerConfigurationStore` 隔离地址与 Keychain 的启动、验证后保存语义。`TrafficMonitoringCoordinator` 管理运行切换、取消来源和过期运行隔离，`TrafficMonitoringRun` 管理地址验证、鉴权、运行配置摘要、自动重连与退避，`MihomoMonitoringSession` 管理一条 WebSocket 实时流、目录刷新和存活检测。

`ConnectionLivenessWatchdog` 独立管理数据超时提示、强制重连阈值、流代次和稳定连接判断。`TrafficMeasurementSession` 组合代理分类、连接增量和速率窗口，统一维护单条实时流的测量基线，并额外输出不经过平滑的原始账本观测。`TrafficStatisticsController` 消费原始观测并维护界面可用性；`SQLiteTrafficLedger` actor 保证增量、累计基线和区间状态原子更新。统计任务仅保存开始和结束时的 Proxy 基线，多个任务共享同一账本。

统计展示分为两层：状态栏弹层中的 `TrafficStatisticsSummaryView` 只展示累计摘要和最多三个活动任务，
`TrafficStatisticsWindowController` 使用普通可缩放窗口承载完整任务筛选、行内编辑和危险操作确认。
两层界面共享同一个 `TrafficStatisticsController`，不会复制账本或建立第二套统计状态。

额度账本同时支持“唯一运行态订阅”和“Clash Profile UID”两种身份，后者只持久化 UID
和订阅地址指纹，不保存订阅 URL。同一本地订阅可以改名和更新地址指纹，但不能静默替换身份模式或 Profile UID；身份变化必须由后续显式迁移流程处理。原始 `upload`、`download`、`total` 与 `expire` 作为机场侧额度观测保存，剩余流量由同一快照计算；使用量下降时开启待确认的新额度周期，趋势只使用最新周期，避免把额度重置前后的数据连成同一条消耗曲线。

`AppDelegate` 为实时流量与配额观察共享同一个 `MihomoControllerClient`；`TrafficMonitor` 只在 Controller 校验成功后启动配额观察，并在断开、重连或终止状态停止。`RuntimeQuotaObservationCoordinator` 启动时立即读取一次，随后每 5 分钟只读请求 `/providers/proxies`，只把必要字段转换为候选，不调用 Provider 更新接口。`RuntimeQuotaTrackingController` 要求恰好一个有效候选和用户明确确认后才记录；零个、多个、运行来源变化或 Controller 地址变化都会暂停，不猜测 Profile 归属。

轻量模式只持久化本地 UUID 和“当前运行订阅”身份，不保存运行时 Provider 键，也不声称识别了 Clash Profile UID。应用重启后无法利用 Provider 键验证同一来源，且同一运行来源背后的 Profile 切换仍可能不可感知；指定 Profile 授权、UID 映射和主动查询留给阶段 2.3 之后实现。

展示层现在使用统一统计工作台：侧边栏只切换“Proxy 流量”和“订阅余额”模块，不承载 Profile 列表；订阅余额模块以自适应实体卡片网格展示同一趋势窗口。状态栏弹层直接展示轻量订阅的剩余量和紧凑走势图，两个“查看全部”入口打开同一窗口并定位对应模块。

展示层采用原生扁平表面层级：孤立只读指标不使用中性圆角卡片，成对指标通过等宽网格与短竖向分隔线组织；需要同屏区分多个 Profile 的订阅实体可以使用中性圆角卡片，但卡片内部指标仍保持扁平。弹层一级区域和普通任务行使用系统 `Divider` 分组，行内编辑器使用上下分隔线界定临时操作范围。只有删除确认、错误或严重警告可以使用同时包含图标和文字的语义色背景，不增加自定义阴影、描边或额外模糊。

## 职责增长边界

为避免 `TrafficMonitor` 再次膨胀，后续改动按以下边界落位：

1. 新增界面状态或文案转换时，扩展 `TrafficMonitorState` 与 `TrafficMonitorReducer`。
2. 新增连接触发方式、运行替换或取消诊断时，扩展 `TrafficMonitoringCoordinator`。
3. 新增鉴权、重试条件、退避或终止错误映射时，扩展 `TrafficMonitoringRun`。
4. 新增单流存活判断、快照接收或代理目录刷新时，扩展 `MihomoMonitoringSession`。
5. 新增分类、连接增量或速率计算时，扩展 `TrafficMeasurementSession` 及对应领域类型。
6. 新增配置与凭据持久化语义时，扩展 `ControllerConfigurationStore`，不得从界面层直接访问 Keychain。
7. 测试按配置、生命周期、状态归约和单流会话分别维护；共享替身放在测试支持文件，不再集中回单一测试类。
8. 新增更新策略或发布源时，扩展 `AppUpdateModel` 与 `SparkleAppUpdater`，不从界面直接请求网络或绕过 Sparkle 验签。
9. 新增累计、保留或区间任务语义时，扩展 `SQLiteTrafficLedger` 及独立持久化职责，不从速率窗口反推累计。
10. 新增订阅额度身份、观测、周期或趋势语义时，扩展 `QuotaLedgerStoring` 及额度领域类型，不与本机 Proxy 流量账本互相推导或对账。

## 稳定边界

1. Mihomo 集成只使用公开 Controller API。
2. Proxy、DIRECT、REJECT 和未知流量独立建模。
3. 连接级数据只用于内存计算，默认不持久化目标明细。
4. 运行配置摘要和活动规则类型只用于当前弹层展示，不持久化规则匹配内容。
5. 断线时实时速率必须归零，不沿用旧值。
6. 本机累计不等同于机场计费流量。
7. Debug 诊断日志只记录固定脱敏事件，不得接收或推导 Controller Secret。
8. 正式版本固定 Bundle ID 与自签名证书指定要求；证书轮换必须先设计凭据迁移。
9. Sparkle 辅助组件使用各自 Bundle ID 和默认指定要求，不得继承主应用指定要求或获得 Controller Secret 的 Keychain ACL 权限。
10. Xcode 开发构建保留 Library Validation；只有固定自签名正式产物使用专用权限关闭 Library Validation，并必须对挂载后的 DMG 执行无生产副作用的真实启动冒烟。
11. Controller Secret 只进入登录钥匙串，不得进入 SQLite 主库、WAL、SHM 或统计模型。
12. 订阅额度账本只保存本地订阅 UUID、可选 Profile UID、订阅地址指纹和额度观测，不保存订阅 URL 或运行时 Provider 键；额度走势与本机 Proxy 流量统计保持独立。
