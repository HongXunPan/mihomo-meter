# 架构概览

## 目标

Mihomo Meter 采用原生 macOS 技术栈，在状态栏展示经过 Mihomo Proxy 出口的实时网速和累计流量。

## 技术栈

- Swift 6
- AppKit `NSStatusItem`
- SwiftUI
- `URLSession`
- `URLSessionWebSocketTask`
- macOS Keychain

SQLite 将在 MVP-2 统计账本阶段引入，MVP-1 不持久化流量累计。

## 分层

```text
状态栏与详情界面
        ↓
流量应用服务
        ↓
Mihomo Controller 集成
        ↓
本地流量账本与 Keychain
```

### Application

负责应用生命周期和模块装配，不承载连接分类或累计算法。

### Domain

保存与界面和网络实现无关的流量模型、分类规则和统计口径。

### Infrastructure

负责 Mihomo Controller、WebSocket、Keychain 和 Debug 诊断日志等系统能力。诊断事件、连接错误映射和文件写入相互分离；日志只接收类型化事件，不接收 Secret、服务地址、原始错误文本或真实响应。

### Presentation

负责状态栏、弹层和用户可见状态，不直接解析 Mihomo 响应。

### 当前模块

MVP-1 已按职责实现：

- `MihomoControllerClient`
- `ConnectionStreamCollector`
- `ProxyCatalog`
- `ConnectionDeltaTracker`
- `ProxyClassifier`
- `TrafficAggregator`
- `DebugDiagnosticLogger`
- `AppDiagnosticEvent`
- `ConnectionDiagnosticReason`

`TrafficMonitor` 负责编排验证、采集、重连和界面状态，不承载分类算法。`TrafficLedger` 将在 MVP-2 进入长期统计时引入。

## 稳定边界

1. Mihomo 集成只使用公开 Controller API。
2. Proxy、DIRECT、REJECT 和未知流量独立建模。
3. 连接级数据只用于内存计算，默认不持久化目标明细。
4. 断线时实时速率必须归零，不沿用旧值。
5. 本机累计不等同于机场计费流量。
6. Debug 诊断日志只记录固定脱敏事件，不得接收或推导 Controller Secret。
