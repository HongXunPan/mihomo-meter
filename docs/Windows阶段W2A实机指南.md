# Windows 阶段 W2A 实机指南

## 1. 用途与边界

本文用于在 Windows 10 22H2 x64 标准用户环境验证 W2A 核心流量账本。W2A 预览产物只增加分类累计和重启恢复，不包含统计任务、订阅余额、连接分析、安装器或稳定更新。

GitHub Actions 通过只证明静态契约、单元测试、Release 构建和非打包发布成功，不能替代系统 SQLite、真实 Controller、应用重启和生命周期实机结果。

## 2. 准备与启动

1. 从目标提交的“Windows 构建与测试”工作流下载 `mihomo-meter-windows-w2a-x64-<提交>` artifact 并完整解压。
2. 记录提交 SHA、工作流链接、Windows 版本、Mihomo 版本；使用标准用户启动，不以管理员运行。
3. 准备可分别制造 Proxy 与 DIRECT 流量的测试条件，不在反馈中暴露节点、目标、规则、订阅或 Secret。
4. 记录是否已经存在旧的 `%LOCALAPPDATA%\HongXunPan\MihomoMeter\traffic.sqlite3`；首次测试建议使用没有 W2A 数据库的环境。

## 3. 累计与恢复

1. 连接后确认实时速率仍正常，初始累计为零或既有历史，不把首帧内核累计直接加入账本。
2. 分别制造 Proxy 与 DIRECT 流量，确认今日和历史总计对应分类增加；未知不得进入 Proxy。
3. 关闭主窗口再继续制造流量，重新打开后累计应继续变化，通知区域监控不停止。
4. 从通知区域明确退出并重新启动，确认今日与历史累计恢复且没有明显重复。
5. 停止并恢复 Mihomo，确认历史累计不清空；恢复后的无法分类缺口只允许进入未知。
6. 若方便跨本地零点测试，确认零点后的增量进入新“今日”，历史总计保持连续；无法覆盖时如实记录。

## 4. 数据与隐私检查

数据库固定位置：

```text
%LOCALAPPDATA%\HongXunPan\MihomoMeter\traffic.sqlite3
```

同目录允许出现 `traffic.sqlite3-wal` 与 `traffic.sqlite3-shm`。不得出现第二份 `e_sqlite3.dll`，数据库和相邻文件不得包含 Secret、Controller 地址、节点、主机、IP、端口、连接 ID、进程路径、规则正文或原始响应。

本轮不提供清空统计界面。需要重置预览数据时必须先从通知区域明确退出，再由测试者手动删除 `traffic.sqlite3`、`traffic.sqlite3-wal` 和 `traffic.sqlite3-shm`；不得删除 `settings.json` 或 Credential Manager 凭据来冒充统计清理。

## 5. 故障与生命周期

1. 将统计目录临时设为不可写或使用其他安全方式制造数据库不可用时，累计区域应显示“本地统计暂不可用”，实时分类速率仍继续；若不便安全复现可记为未覆盖。
2. 连续启动两次仍只保留一个进程；关闭主窗口只隐藏，通知区域和累计继续工作。
3. 睡眠恢复后不得出现重复 WebSocket、重复累计、重复通知区域图标或悬浮窗口。
4. 明确退出后不残留进程、窗口或通知区域图标；再次启动时开放会话应按最后成功观测收口。

账本故障导致实时监控停止、累计明显翻倍、历史被 Mihomo 重启清空、未知进入 Proxy、数据库出现敏感信息或需要管理员权限时，立即停止验收。
