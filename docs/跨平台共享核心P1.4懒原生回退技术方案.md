# 跨平台共享核心 P1.4 懒原生回退技术方案

## 1. 文档定位

- 状态：P1.4-3 完整速率已切换，紧凑速率仍逐次对照
- 更新日期：2026-08-12
- 前置门禁：P1.3 双端运行态验收已通过
- 目标：共享核心成功时不再逐次计算原生文本，共享路径异常时仍立即回退原生算法

P1.4 只优化字节数、完整速率和紧凑速率三类已通过验收的纯格式化路径。它不删除原生格式化实现，不扩大到 View、窗口生命周期、网络、Controller 解码、凭据、SQLite、本地化文案或异步调度，也不以“已经验收过”为理由一次性切换三类格式。

## 2. 决策与替代方案

P1.3 每次格式化都先计算原生文本，再调用共享核心，只有文本精确一致时才返回共享文本。该方式回滚稳定，但生产路径长期重复执行两套算法，不能形成真正由公共实现承担成功路径的结构。

P1.4 采用**共享优先、原生懒回退**：平台路由器先调用共享核心并渲染文本；ABI 不匹配、动态库调用失败、结果结构无效或未知异常时，才调用平台提供的原生回退闭包并返回其文本。成功路径不得求值原生闭包，失败路径必须且只能求值一次。

不采用以下方案：

- **直接删除原生实现**：失去单格式快速回滚和运行时故障隔离，不可接受；
- **保留逐次比较但异步执行**：仍支付双算法成本，并引入顺序、线程和诊断复杂度；
- **增加用户开关或远程开关**：扩大配置、测试和隐私边界，且无法替代源码级分阶段门禁；
- **一次切换三类格式**：故障时无法按格式归因和回滚。

## 3. 路由与诊断契约

Swift 路由入口接收 `nativeFallback: () -> String`，C# 接收同语义的 `Func<string>`。共享调用、共享文本渲染和粗粒度错误映射由路由器负责；原生闭包仍指向现有平台格式化函数，不复制 Rust 算法。诊断回调失败不得触发原生回退，也不得改变已经选择的返回文本。

P1.4-1 已新增独立懒路由结果与路由状态，同时保留 P1.3 对照结果和影子状态。P1.4-2 切换双端 `byte_count`，P1.4-3 再切换 `rate`；只有 `compact_rate` 仍显式先计算原生文本并进入 `resolve` / `Resolve`。

P1.4 不再把成功状态记为 `matched`，因为生产成功路径不执行原生算法，不能声称本次已比较。双端新增独立路由状态 `succeeded`，正常事件为：

```text
event=shared_core.traffic_route format=<format> result=shared_primary status=succeeded
```

回退事件继续使用 `result=native_fallback`，状态只允许 `abi_mismatch`、`native_call_failed`、`unexpected_result` 或 `unknown_failure`。`mismatch` 只保留为差分测试失败，不再作为 P1.4 生产路由状态。事件仍按“格式 + 来源 + 状态”在单次进程内去重，不记录输入字节、共享或原生文本、路径、异常详情、Secret 或连接目标。

## 4. 确定性差分与自动化门禁

移除运行时逐次比较前，双端测试必须继续调用真实原生格式化器与真实共享适配器，并对以下确定性输入逐项比较最终文本：

1. 现有 `SharedCore/TestVectors/traffic_scale.json` 全量值；
2. 每个十进制单位、精度与舍入阈值两侧的固定邻域；
3. 固定种子生成的至少 10,000 个 `UInt64` 样本；
4. `0`、`UInt64.max`、Byte 不显示小数及紧凑速率无值分支。

Swift 与 C# 还必须验证：成功路径原生闭包调用次数为零；每类共享失败的原生闭包调用次数为一；原生回退文本原样返回；诊断失败不追加原生计算；ABI 失败发生在缩放前；共享结果结构无效不会越过路由器。测试生成器固定种子和样本数，不引入 property-testing 第三方依赖。

CI 继续执行 Rust 单测、统一向量、Swift 测试、C# Core 测试、macOS 构建和 Windows 发布打包。计时测试不作为合并门禁；是否消除重复计算由闭包调用次数和调用点静态契约确定，避免 runner 波动导致伪性能结论。

## 5. 分阶段实施

| 阶段 | 交付 | 生产返回路径 | 合并门禁 |
| --- | --- | --- | --- |
| P1.4-0 | 本方案与静态契约 | 三类格式继续 P1.3 逐次对照 | 文档、静态契约与双端 CI |
| P1.4-1 | 双端懒回退路由、独立状态与扩展差分测试 | 三类格式继续 P1.3 逐次对照 | 闭包次数、错误映射、确定性差分与双端构建 |
| P1.4-2 | `byte_count` 切换 | 字节数共享优先；其余逐次对照 | 单格式静态契约、回退测试与双端 CI |
| P1.4-3 | `rate` 切换 | 字节数与完整速率共享优先 | 单格式静态契约、回退测试与双端 CI |
| P1.4-4 | `compact_rate` 切换 | 三类格式均共享优先 | 单格式静态契约、回退测试与双端 CI |
| P1.4-5 | 双端实机验收与状态收口 | 保持三类共享优先、原生懒回退 | 双端运行态门禁与用户确认 |

每一阶段使用独立分支和 PR，PR 与合并后 `main` 门禁通过后才能继续。P1.4-1 只建立新路径，不允许顺带切换生产调用点；P1.4-2 至 P1.4-4 每次只切换一个格式。

## 6. 实机、回滚与停止条件

P1.4-5 要求 macOS 与 Windows 各至少两次独立启动，其中一次为冷启动；每个平台至少连续连接 30 分钟并覆盖“空闲 → 产生流量 → 再次空闲”。三类格式都必须出现一次 `result=shared_primary status=succeeded`，不得出现任何 `native_fallback`、旧的生产 `status=matched`、重复诊断失控、展示变化、启动异常、敏感内容或明显性能退化。

单格式回滚只把对应调用点恢复为 P1.3 逐次对照入口，不修改 ABI、数据或用户设置。P1.4 完成后仍保留原生实现、P1.3 对照路由和确定性差分测试，后续删除必须另行设计。

出现以下任一情况立即停止后续阶段：共享成功路径仍求值原生闭包；共享失败未恰好回退一次；成功事件仍声称 `matched`；差分样本不一致；必须引入运行时开关或第三方测试依赖；错误越过路由器影响监控；原生实现被删除；三类格式不能独立切换或回滚；任一平台 CI 或实机门禁失败。
