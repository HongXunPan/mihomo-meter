# Windows 阶段 W2D-0 实机指南

## 1. 验收定位

本指南用于 Windows 10 22H2 x64 标准用户验证连接分析元数据是否可用。执行前确认对应提交的“Windows 构建与测试”成功，再下载名称以 `mihomo-meter-windows-w2d-x64-` 开头的 artifact。

W2D-0 只展示聚合覆盖率，不展示或保存真实主机名、进程名、进程路径与连接 ID。不要上传 Controller Secret、订阅 URL、节点、真实响应、数据库或本机路径。

## 2. 前置准备

1. 使用与 W2C 相同的 Clash Verge Rev/Mihomo 与 Controller 配置。
2. 解压新的 W2D artifact 到普通用户可写目录并启动应用。
3. 准备两个明确经过 Proxy 的受控场景：一个浏览器网页或下载，另一个非浏览器联网应用；不需要暴露访问目标。
4. 保持标准用户权限，不以管理员身份启动 Meter 或 Mihomo 客户端。

## 3. 自动化与既有能力

1. 确认 Action 中静态检查、Core 单元测试、Release 构建和自包含发布全部成功。
2. 连接 Controller，确认 Proxy、DIRECT、REJECT、未知速率和分类覆盖率仍正常刷新。
3. 快速检查 Proxy 流量、统计任务、订阅余额、通知区域、关闭隐藏和明确退出无回归。

任一 W0-W2C 已通过能力回归，应停止本次验收并报告。

## 4. 覆盖率验证

1. 在“实时监控”底部找到“连接分析 W2D-0”区域，确认只显示四项数字和隐私说明，没有主机名、进程名、进程路径或连接 ID。
2. 先打开一个明确经过 Proxy 的网页或下载，等待 Proxy 连接样本增加。
3. 再使用一个明确经过 Proxy 的非浏览器应用，观察样本与应用可识别数量是否继续变化。
4. 保持相同连接活动一段时间，确认样本按连接去重，不随每个 500 毫秒快照无界增加；后续识别到元数据时允许已有样本比例上升。
5. 记录最终四项聚合结果：Proxy 样本、主机名可识别、应用可识别、两者同时可识别。只需数字，不需要目标或应用名称。

若 Proxy 速率有真实变化但样本一直为零，先确认分类覆盖率；可靠 Proxy 样本存在而主机名或应用识别始终为零时，直接记录失败，不使用 IP、节点、规则或日志补位。

## 5. 清理语义

1. 主动断开再重新连接，确认四项样本先清零，再从新会话重新累计。
2. 若测试环境自然发生 stale 或 Mihomo 计数器重置，确认样本被清空；不要为了触发该条件修改真实数据库或破坏客户端配置。
3. 退出并重启应用，确认上次覆盖率样本不会恢复。

## 6. 通过标准与反馈

通过需要同时满足：对应 CI 全绿；可靠 Proxy 样本能够产生；主机名与应用识别数量均出现非零结果；同连接不会按快照重复计数；新会话会清空；界面、日志与三个业务数据库没有新增敏感连接字段；W0-W2C 无回归。

反馈只需提供：四项最终数字、使用了浏览器与非浏览器两类受控场景、失败步骤、预期/实际和 Action run 链接。W2D-0 通过后再进入实时连接 W2D-1；本 artifact 不用于验证历史归因。
