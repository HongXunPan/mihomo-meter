# 阶段 2 订阅余额人工验收清单

本清单用于完成自动化检查无法替代的 macOS 界面与真实环境验收。测试时不要在截图、日志或反馈中暴露订阅地址、Token、节点名称或完整 Profile 路径。

## 验收前准备

- [ ] 当前分支远端 CI 的格式、脚本、无签名构建和测试全部通过。
- [ ] 准备一个可由 Mihomo 暴露配额的当前订阅。
- [ ] 如需验证指定 Profile，再准备至少两个远程订阅 Profile，并确认其中一个是当前 Profile。
- [ ] 记录测试前是否已经授权 Profile 目录，便于核对清除行为。

## 轻量模式

- [ ] 未授权 Profile 目录时，状态栏弹窗只在 Mihomo 暴露唯一有效配额候选后提供轻量追踪确认。
- [ ] 确认后显示剩余流量、已用、总量、更新时间、趋势和预计耗尽状态。
- [ ] 样本不足时显示明确原因，不显示伪造的预计天数。
- [ ] 候选变为零个、多个或来源变化时自动暂停，不继续猜测归属。

## 指定 Profile 模式

- [ ] 首次选择 Profile 目录只弹出一次系统授权；重新启动后可恢复授权，不重复弹窗。
- [ ] 当前 Profile 默认展开，非当前 Profile 收起并显示名称、剩余量、更新时间和查询状态。
- [ ] 弹窗使用原生扁平分区、留白和分隔线，不为 Profile 增加白底圆角卡片。
- [ ] 手动查询和全部查询必须经过当前 Mihomo；Mihomo 不可用时按钮禁用并保留最近历史。
- [ ] 完整统计窗口通过侧边栏进入“订阅余额”，同屏显示多个 Profile，不出现左侧 Profile 列表与右侧详情布局。

## 趋势与变化事件

- [ ] 观察不足 6 小时、数据过期、近期无消耗、订阅到期或额度耗尽时显示对应原因。
- [ ] 用量下降后出现“待确认新周期”，确认前不输出耗尽预测。
- [ ] 点击“确认新周期”后警告消失，新周期积累足够样本后恢复预测。
- [ ] 总额度增加、总额度减少或到期时间变化后，在对应 Profile 中显示变化摘要。
- [ ] 24 小时、7 天和 30 天切换始终展示剩余流量走势，不把上传或下载误当作剩余量。

## 清除与隐私

- [ ] 完整订阅余额窗口的更多菜单提供“清空订阅余额数据”，弹窗明确说明删除和保留范围。
- [ ] 确认清除后，轻量订阅、Profile 选择、趋势、变化事件和查询状态全部归零。
- [ ] 清除后 Controller 地址与 Secret 仍可使用，Profile 目录授权仍然有效，但 Profile 需要重新选择。
- [ ] Proxy 流量统计和秒表式任务不受订阅余额清除影响。
- [ ] 诊断日志不出现 Profile 名称、真实 UID、订阅地址、Token、UA 原文、完整响应头或正文。

## 验收结论

- [ ] 以上项目全部通过。
