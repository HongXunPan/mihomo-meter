# 订阅配额架构

## 范围

订阅配额与本机 Proxy 流量使用不同身份、账本和统计口径。机场配额可能包含其他设备、线路倍率、协议开销和机场计费规则，不与本机流量账本做差值对账。

阶段 2.2 提供“当前运行订阅”轻量模式；阶段 2.3 在同一额度领域上增加 Clash Profile 身份控制面；阶段 2.4 通过当前 Mihomo 本地代理主动查询选中的 Profile，并提供多 Profile 展示。高级预测和阶段 2 完整验收属于后续阶段。

## 当前运行订阅轻量模式

```text
Mihomo /providers/proxies
            ↓
RuntimeQuotaObservationCoordinator
            ↓
RuntimeQuotaTrackingController
       ↙                         ↘
SQLiteQuotaLedger             弹层扁平分区与统一统计窗口
      ↓
quota.sqlite3 → 额度周期识别与趋势计算
```

`AppDelegate` 为实时流量与配额观察共享同一个 `MihomoControllerClient`。`TrafficMonitor` 只在 Controller 校验成功后启动配额观察，并在断开、重连或终止状态停止。`RuntimeQuotaObservationCoordinator` 启动时立即读取一次，随后每 5 分钟只读请求 `/providers/proxies`，只把必要字段转换为候选，不调用 Provider 更新接口。

`RuntimeQuotaTrackingController` 要求恰好一个有效候选和用户明确确认后才记录；零个、多个、运行来源变化或 Controller 地址变化都会暂停，不猜测 Profile 归属。该模式只持久化本地 UUID 和“当前运行订阅”身份，不保存运行时 Provider 键，也不声称识别了 Clash Profile UID。应用重启后无法利用 Provider 键验证同一来源，且同一运行来源背后的 Profile 切换仍可能不可感知。

## 指定 Profile 身份控制面

```text
用户选择 Profile 目录
          ↓
只读安全范围书签 ←→ 目录观察器（400 ms 防抖）
          ↓
profiles.yaml → Yams 类型化解析 → ClashProfileDirectoryController
                                         ↓
                              ClashProfileTrackingService
                                  ↙                 ↘
                    Keychain HMAC 指纹密钥       SQLiteQuotaLedger
                                                       ↓
                                        Profile UID、名称、地址指纹与间隔
```

Profile 目录通过用户选择的只读安全范围书签恢复访问。`YAMLClashProfileCatalogReader` 只读取 `profiles.yaml` 的 `current`、`items[].uid`、`type`、`name` 和 `url`；Presentation 不直接解析 YAML。目录变化只触发防抖重读和身份状态协调，本身不写配额快照；已追踪 Profile 的 URL 指纹变化后，独立查询调度器会把新地址视为立即到期任务。

指定 Profile 以 UID 建立精确身份：

- 改名只更新展示名称。
- 地址重置只更新 HMAC-SHA256 指纹。
- 删除后以新 UID 重新导入不会继承旧身份或历史。
- 原始 URL 只在安全范围访问期间保留于内存，不进入持久化或界面状态。
- 每个已选择 Profile 保存独立观察间隔，不跟随 Clash Verge 自动刷新周期。

Controller Secret 和 Profile 地址指纹密钥使用不同的传统登录钥匙串服务项，均不进入 SQLite。安全范围访问必须在目录观察生命周期中成对开启和关闭；停止访问会删除书签，但不隐式删除额度账本中的身份或历史。

## 指定 Profile 主动查询

```text
profiles.yaml 中已选 Profile
             ↓ 临时 URL、UID 与独立查询间隔
ProfileQuotaTrackingController
             ↓
ProfileQuotaQueryWorker（全局单并发）
             ↓
MihomoActiveQuotaQueryClient → 当前 Mihomo 本地代理 → 机场 HTTPS 订阅地址
             ↓
Subscription-Userinfo 响应头 → SQLiteQuotaLedger → 快照与趋势
```

`TrafficMonitor` 只在 Controller 校验成功且 `/configs` 暴露代理端口时把代理配置交给查询控制器。代理选择优先级为 mixed、HTTP、SOCKS；没有可用端口时保持最近有效快照并等待，不静默改为直连。查询 UA 优先复用 `/configs` 的 `global-ua`，缺失、空白或包含不安全控制字符时使用 Mihomo 默认值 `clash.meta`；不伪装特定 Clash Verge 版本，也不对同一轮查询重复尝试多个 UA。请求只接受 HTTPS，重定向目标仍必须是 HTTPS，使用 15 秒超时和临时 `URLSession`，取得响应头后取消正文。

`SubscriptionUserInfoParser` 兼容大小写不敏感、分号分隔的 `upload`、`download`、`total` 和可选 `expire` 字段。原始字段用于额度账本，剩余量由同一快照计算；响应正文、完整响应头和原始订阅 URL 均不保存。

`ProfileQuotaQueryWorker` 使用全局单并发队列。每个 Profile 可选择 1、3、6、12 或 24 小时间隔，默认 6 小时；自动任务增加 0 至 30 秒随机抖动。失败按 5 分钟、15 分钟和 60 分钟退避，每个 Profile 每个本地自然日最多执行 3 次自动重试，之后回到常规周期。手动查询有 60 秒冷却，并与自动任务共用同一并发边界。失败不会写入零值或覆盖最近有效快照。

查询状态单独保存在 `quota_query_state`，只包含上次和下次尝试时间、已查询 URL 指纹、连续失败数、重试日和自动重试次数，不保存 URL、响应正文或原始错误文本。查询开始、成功、取消和失败会另行写入有容量与保留期限限制的类型化本地诊断日志，供用户从帮助菜单打开日志目录后复制反馈；该日志不进入配额账本，也不自动上传。

## 账本与趋势

额度账本同时支持“唯一运行态订阅”和“Clash Profile UID”两种身份。Profile 身份只持久化 UID、展示名称、订阅地址指纹和观察间隔，不保存订阅 URL，也不能静默替换身份模式或 UID。

原始 `upload`、`download`、`total` 与 `expire` 作为机场侧额度观测保存，剩余流量由同一快照计算。使用量下降时开启待确认的新额度周期，趋势只使用最新周期，避免把额度重置前后的数据连成同一条消耗曲线。

## 展示边界

统一统计工作台的侧边栏只切换“Proxy 流量”和“订阅余额”，不承载 Profile 列表。订阅余额模块通过自适应卡片网格同屏展示已选 Profile 的配额、状态和同一趋势窗口；支持单项查询、全部查询，授权与选择集中在管理弹窗中。

状态栏弹层在没有已选 Profile 时继续展示轻量订阅；存在精确追踪目标时改为单开手风琴，默认只展开当前 Profile，非当前 Profile 收起并显示剩余量和查询状态。Profile 展开行沿用弹层现有的原生扁平层级，以留白和分隔线组织，不增加圆角卡片背景；展开项展示紧凑走势图和手动查询入口。

展示采用原生扁平表面层级：孤立只读指标不使用中性圆角卡片，成对指标通过等宽网格与短竖向分隔线组织；只有完整统计窗口中需要同屏区分多个 Profile 的订阅实体可以使用中性圆角卡片，卡片内部指标仍保持扁平。只有删除确认、错误或严重警告可以使用同时包含图标和文字的语义色背景。

## 职责增长边界

1. 新增订阅额度身份、观测、周期或趋势语义时，扩展 `QuotaLedgerStoring` 及额度领域类型，不与本机 Proxy 流量账本互相推导或对账。
2. 新增 Profile 文件字段或兼容规则时，扩展类型化 YAML 模型和 `ClashProfile`，不得从界面层直接解析字典或保存原始订阅 URL。
3. 新增目录授权或监听策略时，扩展 `ProfileDirectoryAccessing` 协议族和基础设施实现，必须维持安全范围访问的成对启停。
4. 主动查询必须由独立控制器和单并发调度器通过当前 Mihomo 本地代理发起，不复用 Clash Verge 私有 IPC，也不允许 Presentation 直接发起网络请求。
5. 查询诊断由 `ProfileQuotaQueryExecutor` 发出类型化事件，Worker 不拼装日志文本；日志只记录本地订阅 ID、短地址指纹、触发来源、当前状态、代理类型、UA 来源分类、固定结果分类、状态码、耗时和重试间隔，不记录 UA 原文。

## 稳定边界

1. 订阅额度账本只保存本地订阅 UUID、可选 Profile UID、订阅地址指纹和额度观测，不保存订阅 URL 或运行时 Provider 键。
2. Profile 目录必须由用户明确选择并以只读安全范围访问；持久化书签只用于恢复该授权，停止访问后不得继续读取。
3. Profile 地址指纹使用应用本地 Keychain 随机密钥计算 HMAC-SHA256，不作为可逆地址副本；原始 URL 不进入 UserDefaults、SQLite、日志或界面状态。
4. 额度走势与本机 Proxy 流量统计保持独立，不互相推导或对账。
5. 主动查询不允许静默直连或降级到 HTTP；错误、响应头和正文不得作为查询状态持久化。
