# 诊断与导出

## 本地诊断日志

Debug 与正式版本均在应用沙盒写入脱敏诊断日志：

```text
~/Library/Containers/com.HongXunPan.MihomoMeter/Data/Library/Logs/MihomoMeter/diagnostics.log
```

日志只记录应用启动与签名粗粒度状态、Keychain 操作阶段和数值状态码、连接取消与重连原因、共享核心路由状态，以及 Profile 配额查询的本地标识、短指纹和类型化结果。它不记录 Controller Secret、地址及长度、Profile 名称或真实 UID、订阅地址、Token、节点、UA 原文、请求或响应、错误原文、完整路径或连接目标，也不上传。

单文件上限 512 KiB，只保留当前与一份轮换日志；超过 7 天未更新会在下次写入前删除。帮助菜单可打开诊断目录；应用停止后可删除日志，后续会按需重建。

仅 Debug 构建可通过环境变量 `MIHOMO_METER_DIAG_PERFORMANCE=1` 开启本进程性能采样：启动后每 1 分钟写入一次，最多 720 条（约 12 小时），退出时停止。每条只含固定状态栏展示模式、连接开始时间解析标记（`date_parser_mode=format_style`）、采样间隔内的 CPU 百分比（`cpu_percent_tenths`，单核 100% 对应数值 1000）、当前常驻内存 MiB（`rss_mib`，读取失败时为 `unknown`），以及同一分钟内成功解码的 `/connections` 快照数（`connection_snapshots`）、单次快照连接数最小至最大值（`connection_count_range`，无快照时为 `unknown`）、累计解码耗时毫秒数（`connection_decode_ms`）、快照数据总字节数（`snapshot_bytes_total`）、连接条目总数（`connection_entries_total`）和单帧最长解码耗时毫秒数（`connection_decode_max_ms`）。耗时是墙钟时间，不等同于 CPU 用时；字节数只取解码时已生成的数据长度。这些聚合值不记录连接 ID、名称、目标或响应内容，不自动上传，也不进入用户诊断导出；未启用时不运行采样任务，也不计量解码。日志仍遵循单文件 512 KiB、当前与一份轮换日志的容量上限，其他诊断事件较多时可能无法保留完整 12 小时记录。

`/connections` 的连接开始时间在 Debug 与正式构建中统一使用 `Date.ISO8601FormatStyle`；按输入是否包含小数秒选择对应样式，不再使用旧解析器或解析模式环境变量。历史诊断日志可能仍含 `legacy` 标记；最低支持系统上的实际解析与性能仍需由完整门禁和实机验收确认。

双行状态栏默认由单个 AppKit `NSView` 绘制，性能记录写入 `display_mode=direct_draw`；仅 Debug 单行诊断写入 `native_single_line`。旧的多控件展示模式与切换环境变量不再使用，历史日志中的 `stacked_controls` 仍可用于对照。

## 用户诊断导出

macOS 与 Windows 均在设置页提供“导出诊断信息”。应用先展示包含与排除范围，用户确认后再由系统保存面板选择位置；取消选择不会生成文件，文件也不会自动上传。

导出文件是 UTF-8 JSON v1，只包含：

- 应用版本与构建号；
- 系统版本与架构；
- 固定连接状态；
- 当前会话最多 200 条脱敏事件。

事件来自独立的内存白名单快照，不读取原始日志；固定类别之外只允许固定状态、数值错误码、耗时、超时和退避。Windows 当前会话与 macOS 对齐覆盖凭据读取/保存/删除、连接尝试/建立/stale/取消/重连/停止，以及 Profile 配额查询开始与结束；平台名称可以不同，但事件语义和排除范围一致。

## 排除范围

导出文件不包含：

- Controller 地址或 Secret、Keychain/Credential 内容；
- `traffic.sqlite3`、`quota.sqlite3`、`connection-analytics.sqlite3`；
- 请求标识、订阅 UUID、Profile UID、地址指纹或业务名称；
- 文件路径、主机名、应用名、连接目标、节点或规则；
- 原始错误文本、日志原文、请求或响应内容。

Windows 对自由文本事件字段还执行固定字符集和长度校验，不满足白名单时写入 `unknown`，不会原样进入文件。

## 验收边界

自动测试覆盖 JSON v1、200 条上限、标识符剔除和非法自由文本降级。macOS 的完整构建由 CI 门禁执行，Windows 的完整构建由 Windows CI 执行；两端仍需实机确认范围提示、取消不写文件、覆盖保存、权限拒绝和文件内容。
