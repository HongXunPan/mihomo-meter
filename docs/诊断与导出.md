# 诊断与导出

## 本地诊断日志

Debug 与正式版本均在应用沙盒写入脱敏诊断日志：

```text
~/Library/Containers/com.HongXunPan.MihomoMeter/Data/Library/Logs/MihomoMeter/diagnostics.log
```

日志只记录应用启动与签名粗粒度状态、Keychain 操作阶段和数值状态码、连接取消与重连原因、共享核心路由状态，以及 Profile 配额查询的本地标识、短指纹和类型化结果。它不记录 Controller Secret、地址及长度、Profile 名称或真实 UID、订阅地址、Token、节点、UA 原文、请求或响应、错误原文、完整路径或连接目标，也不上传。

单文件上限 512 KiB，只保留当前与一份轮换日志；超过 7 天未更新会在下次写入前删除。帮助菜单可打开诊断目录；应用停止后可删除日志，后续会按需重建。

仅 Debug 构建可通过环境变量 `MIHOMO_METER_DIAG_PERFORMANCE=1` 开启本进程性能采样：启动后每 1 分钟写入一次，最多 720 条（约 12 小时），退出时停止。每条记录包含固定状态栏展示模式、连接开始时间解析标记（`date_parser_mode=format_style`）、采样间隔内的 CPU 百分比（`cpu_percent_tenths`，单核 100% 对应数值 1000）、当前常驻内存 MiB（`rss_mib`，读取失败时为 `unknown`），以及同一分钟内成功解码的 `/connections` 快照数（`connection_snapshots`）、单次快照连接数最小至最大值（`connection_count_range`，无快照时为 `unknown`）、累计解码耗时毫秒数（`connection_decode_ms`）、快照数据总字节数（`snapshot_bytes_total`）、连接条目总数（`connection_entries_total`）和单帧最长解码耗时毫秒数（`connection_decode_max_ms`）。

同一条记录还包含原生实时连接表是否仍挂载（`live_table_mounted`，1 或 0）、本分钟挂载与卸载次数（`live_table_mounts`、`live_table_unmounts`）、表格行数范围（`live_table_rows_range`，无更新时为 `unknown`）、更新回调次数（`live_table_updates`）、跳过更新次数（`live_table_skipped_updates`）、整表刷新次数（`live_table_reloads`）、增量更新批次数（`live_table_incremental_batches`）、行移动、插入和删除次数（`live_table_row_moves`、`live_table_row_insertions`、`live_table_row_removals`）、AppKit 单元格配置次数（`live_table_cells`）、直接更新可见单元格次数（`live_table_visible_cell_updates`），以及表格同步更新回调累计和单次最长耗时毫秒数（`live_table_update_ms`、`live_table_update_max_ms`）。空搜索结果或切换到其他维度时，原生表格可能卸载；这些字段只测量该表格，不代表整个统计窗口或 SwiftUI 视图图开销。

仅 Debug 构建可在启用性能采样的同时设置 `MIHOMO_METER_DIAG_FREEZE_LIVE_TABLE=1` 运行一次表格冻结对照。表格连续挂载并完成一整分钟有更新的基线后，下一分钟只暂停向已有表格应用新数据，后台连接采集、解码和排序计算照常进行；随后自动恢复，且本进程不再重复冻结。每条性能记录以 `live_table_freeze_phase` 标记 `baseline`、`frozen`、`resumed` 或未开启时的 `disabled`。仅比较挂载和卸载次数均为 0、快照数量接近的完整基线与冻结分钟；若冻结期间切换页面、搜索结果变空或重连导致表格重建，该轮对照作废。新挂载的空表允许接收首帧数据，避免冻结期间重新打开页面后一直显示空表。关闭该环境变量或使用正式构建不会冻结展示。

仅 Debug 构建可在启用性能采样、关闭冻结对照时设置 `MIHOMO_METER_DIAG_INCREMENTAL_TABLE=1` 试验原生表格增量更新。连接仍按当前速率每次重新排序；当行身份或顺序变化时，表格按 ID 执行成组删除、插入和移动，而不默认整表重载；同顺序的数值变化仍直接更新可见单元格。诊断字段只记录操作次数，不记录连接 ID。若行 ID 重复或表格与数据源行数不一致，则沿用现有整表重载路径。该开关只用于对照，不改变正式构建；比较时应保持窗口、搜索条件及快照数量相近，并注意首次挂载和连接数量波动对结果的影响。

解码与表格耗时均为墙钟时间，不等同于 CPU 用时；表格同步更新耗时也不覆盖其后的异步绘制。字节数只取解码时已生成的数据长度。聚合值不记录连接 ID、名称、目标或响应内容，不自动上传，也不进入用户诊断导出；未启用时不运行采样任务，也不计量解码或表格更新。日志仍遵循单文件 512 KiB、当前与一份轮换日志的容量上限，其他诊断事件较多时可能无法保留完整 12 小时记录。

`/connections` 的连接开始时间在 Debug 与正式构建中统一使用 `Date.ISO8601FormatStyle`；按输入是否包含小数秒选择对应样式，不再使用旧解析器或解析模式环境变量。历史诊断日志可能仍含 `legacy` 标记；最低支持系统上的实际解析与性能仍需由完整门禁和实机验收确认。

双行状态栏默认由单个 AppKit `NSView` 绘制，性能记录写入 `display_mode=direct_draw`；仅 Debug 单行诊断写入 `native_single_line`。旧的多控件展示模式与切换环境变量不再使用，历史日志中的 `stacked_controls` 仍可用于对照。

## 用户诊断导出

macOS 与 Windows 均在设置页提供“导出诊断信息”。应用先展示包含与排除范围，用户确认后再由系统保存面板选择位置；取消选择不会生成文件，文件也不会自动上传。

导出文件是 UTF-8 JSON v1，只包含：

- 应用版本与构建号；
- 系统版本与架构；
- 固定连接状态；
- 当前会话最多 200 条脱敏事件。

事件来自独立的内存白名单快照，不读取原始日志；固定类别之外只允许固定状态、数值错误码、耗时、超时和退避。Windows 当前会话与 macOS 对齐覆盖凭据读取/保存/删除、连接尝试/建立/stale/取消/重连/停止，以及 Profile 配额查询开始与结束；平台名称可以不同，但事件语义和排除范围一致。

## 排除范围

导出文件不包含：

- Controller 地址或 Secret、Keychain/Credential 内容；
- `traffic.sqlite3`、`quota.sqlite3`、`connection-analytics.sqlite3`；
- 请求标识、订阅 UUID、Profile UID、地址指纹或业务名称；
- 文件路径、主机名、应用名、连接目标、节点或规则；
- 原始错误文本、日志原文、请求或响应内容。

Windows 对自由文本事件字段还执行固定字符集和长度校验，不满足白名单时写入 `unknown`，不会原样进入文件。

## 验收边界

自动测试覆盖 JSON v1、200 条上限、标识符剔除和非法自由文本降级。macOS 的完整构建由 CI 门禁执行，Windows 的完整构建由 Windows CI 执行；两端仍需实机确认范围提示、取消不写文件、覆盖保存、权限拒绝和文件内容。
