# WidgetKit 固定自签名专用目录 PoC 验证

本 PoC 只使用假数据，独立于正式 Mihomo Meter。`0.0.3` 已观察到 App Group 运行时授权被拒；`0.0.4` 虽声明了专用目录权限，但主应用实际写入自己的沙盒容器，尚未测到该权限。本版改从系统账户记录取得用户主目录，继续验证主应用对专用目录读写、Widget 对同一目录只读的 macOS 沙盒临时文件例外。CI 静态签名成功不能替代用户安装后的运行时验证。

专用目录固定为 `~/Library/Application Support/com.HongXunPan.MihomoMeter.WidgetSigningPoC/`。主应用写入 `widget-snapshot.txt`，Widget 只读取该文件；两端仍开启沙盒，继续使用原有固定自签名证书。该目录只含假数据，不得写入 Controller Secret、订阅地址、真实流量或配额。

## 安装与复现

1. 从同一次 GitHub Actions artifact 取得 DMG、签名报告、诊断脚本和本说明。确认签名报告说明“主应用读写、Widget 只读”，而不是旧版 App Group。
2. 退出并替换旧 `WidgetSigningPoC.app`，从 DMG 将新版本复制到“应用程序”。打开应用，点击“重新写入假快照”，记录主应用显示的位置分类、目录短指纹、写入与回读结果；随后通过诊断脚本确认已安装版本为 `0.0.5`，用户目录中的专用文件夹和快照文件均存在。
3. 添加或重新添加“Mihomo Meter 签名 PoC”小组件，确认显示“路径诊断版 5”，记录位置分类、目录短指纹、读取结果与错误码。主应用与 Widget 均须显示“用户目录”、目录短指纹相同；必要时移除后重新添加，以排除旧时间线。
4. 复现后尽快在“终端”执行 `bash widgetkit-signing-poc-diagnose.sh`。默认只检查最近 15 分钟；如操作较慢，可传入 1–60 的分钟数，例如 `bash widgetkit-signing-poc-diagnose.sh 30`。

诊断脚本只读已安装 PoC 的签名、系统注册、快照文件存在性与权限模式，并筛选与本 PoC 有关的沙盒日志。它只输出固定状态、计数和短证书指纹，不输出原始系统日志、完整文件路径、快照内容、私钥或业务数据；不使用 `sudo`，不写文件，也不上传数据。日志中没有拒绝记录不能证明 Widget 已获授权，必须与小组件界面的实际读取结果合并判断。

## 证据判读

- `widgetkit-signing-poc-verification.txt` 是 CI 的**静态证据**：确认两个包使用同一固定证书、主应用声明专用目录读写、Widget 声明同目录只读，且嵌入与签名校验通过；它不能证明运行时文件可读。
- 报告与脚本展示的是 `codesign` 指定要求中的叶证书 SHA-1 短指纹；此前手工核验的 SHA-256 是同一证书的另一种摘要，两个字符串不能直接比较。
- 主应用写入和回读成功、诊断脚本确认用户目录中的文件存在、Widget 显示同一目录短指纹且读取成功，才构成本 PoC 的正向运行时证据。任何一项缺失均不能视为通过。
- 若 Widget 读取失败，请同时提供 Widget 界面、主应用界面和诊断脚本输出；系统日志没有拒绝记录并不等于权限成功。不要把旧版 App Group 的日志误判为本版文件权限结果。

PoC 结束后可退出应用，再删除 `~/Library/Application Support/com.HongXunPan.MihomoMeter.WidgetSigningPoC/` 中的假数据。该目录权限为当前用户可访问；同一用户的其他进程理论上也可能读取，不能把 `0700/0600` 当作同用户进程隔离。请勿把真实业务数据或原始系统日志加入此 PoC 或反馈材料。正式 Release 签名与分发体系不受本 PoC 影响。
